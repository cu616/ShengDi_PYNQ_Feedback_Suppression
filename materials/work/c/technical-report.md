### 摘要

声堤面向麦克风与音响位置相对固定的语音扩声。系统以实际播放信号为参考，在可编程逻辑中执行512抽头Q20定点反馈预测，再从麦克风输入中减去预测分量。处理器配置音频Codec、系数与增益，记录版本、运行状态及保护停声原因。v3把增益前残差保留为25位，先乘数字增益再限制输出范围，避免在中间环节提前截断。

已取得的工程证据包括定点核对、仿真、实现报告及A记录的板上检查。固定322 Hz三臂记录的共同含源窗口中，抵消相对旁路的残差差为8.46 dB，麦端差为4.95 dB。该数字来自A在原件旁运行C分析器的派生JSON；本次C核对身份、窗口与差值算术，未取得原始PCM作本地复算。零系数配置另有约60秒持续运行记录。正常语音下抵消的附加收益、可重复ASG和听众声压尚无完整量化验收。

## 1 选题背景与已有方法

扩声系统中，音响输出重新进入麦克风，经过放大后再次播放，形成闭合声反馈回路。稳定性取决于频率相关的环路幅度和相位；单凭路径幅度峰值或“数字增益为负”都不足以判断是否起振。系统目标是在固定几何条件下减少回传分量，保留讲话通路，并保留可恢复的运行控制。

反馈抵消利用参考信号和反馈路径模型估计不需要的回传声，是已有技术。本项目没有把FIR预测或相减本身作为新算法。Rombouts等在面向长声学路径的PEM-AFROW工作中研究非平稳语音与输出参考相关引起的辨识问题[1]。该文采用源模型及预白化，而本项目冻结版本使用离线标定的固定FIR；未实现或验证PEM-AFROW，不能借该文的性能为本项目背书。

PYNQ官方v2.4文档提供PYNQ-Z2、ADAU1761的录放接口说明[2]。Notebook分段录放可帮助检查信号与接线，但不能单独证明连续低延迟扩声。本设计把逐帧预测、残差、数字增益和播放调度放到PL，PS负责控制和证据记录。

### 工程贡献与应用边界

1. 将固定路径预测、实际播放参考和逐帧闭环调度落实到PYNQ-Z2，并保留可追溯的Q20系数及位流/驱动绑定。
2. 修正宽残差在低于单位增益时提前夹紧的数值问题，独立区分输入满幅保护和中间残差越界诊断。
3. 将黄金参考、原始帧域、共同含源窗和幅度单位连接到可执行复核流程，保留错误推断及撤回依据。

固定模型依赖标定时的几何、模拟音量及环境。移动麦克风/音响、改变场景或外部声源处理都可能使模型失配。本稿未承诺动态场景、全频宽或任意语音下免啸叫。

### 验收问题的定义

“能听到声音”回答语音通路问题；同增益受控对照回答该条件下的抵消差异；MSG/ASG需要分别测得旁路与抵消最大稳定增益，并满足重复性和停止判据。三者不能互相替代。静音、限幅或降增益属于控制/保护效果，不计作同等增益下的抵消成功。

## 2 系统原理与软硬件划分

设实际播放参考为u[n]，麦克风信号为m[n]，路径模型为h[k]，冻结模型从前一帧参考开始预测：p[n] = Σ h[k]·u[n-1-k]。抵消残差为e[n] = m[n] - p[n]；旁路臂使用m[n]。播放路径在两帧调度后加入板载受控源s[n]。模型抽头索引和前向两帧调度分别计算，不重复平移。

{{architecture}}

| 组成 | 职责及接口 |
|---|---|
| ADAU1761 / I2S | ADC输入、DAC输出与音频串行传输；采样率48828.125 Hz |
| PL FIR与播放主路 | 512抽头、串行MAC、Q20系数；预测、宽残差、增益、源混合与限幅 |
| PL状态与环形捕获 | 帧计数、饱和/故障状态、16384帧末窗；保存播放/麦端/预测/残差四列 |
| PS Python/PYNQ | 配置Codec、加载整套位流及系数、限时启动、轮询与停止恢复、落盘元数据 |
| 离线B/C工具 | 模型与单位检查、黄金参考、精确round配对和窗口统计；不控制板卡 |

### 数据格式与v3保护

音频PCM为有符号24位，合法范围[-8388608, 8388607]；归一化满幅基准为2^23。系数为signed24、20个小数位；系数可表示约±8不意味着PCM满幅为±8。数字增益使用无符号16位、12个小数位，范围与寄存器约定见v3契约。

预测项单独限幅；麦端减预测项的差用25位保留。v3数字增益作用于此宽残差，之后才做输出限幅，再与板载源相加并检查混合限幅。诊断残差列仍为24位，不能将它当成v3播放主路的增益操作数。

capture_status bit22独立记录输入达到正/负满幅。驱动对输入满幅、预测/增益后/混合饱和及协议/超时故障停声；增益前残差越出旧24位范围只计数。保护触发只能写对应原因，不能写“识别到啸叫”。

## 3 模型、标定与身份绑定

冻结候选为models/room_v1/rewired_512_20261026.json。模型记录512抽头、lag_first=1、ridge=1e-9、bias=0、fixture=room_v1_20261026b、Codec40和48828.125 Hz。训练身份为newlayout-6captures-train4-dev1，验证capture_id为fe709b08-d987-4701-8dd0-d5129062af57。训练/开发/验证实际文件名单最终由B清单确认，本稿不根据名称补造名单。

模型自带验证记录给出14895个评价帧，开环预测误差降低约1.43 dB。它是同次会话的留出开环结果，不能当跨场景泛化、闭环ASG或语音增益收益。模型文件保留当时的offline_candidate_not_board_validated标签；后续板上使用与验收由A的独立证据描述，不回写原模型来改变历史身份。

### 频域与时间域解释

路径模型响应、抵消残差和闭环声学电平回答不同问题。单频三量分开记录：旁路残差与抵消残差之差；旁路麦端相对开环抬升；抵消相对旁路的麦端变化。没有校准听众位置声压、没有稳定阈值扫描，就不把这些量改名成可听收益或ASG。

离线源对齐只用于明确注明的诊断；冻结模型与未平移原时序的留出结果不能被对齐后的好看数字替代。测试夹具、源身份、参数和窗口必须随模型保留。实际Q20数组按little-endian int32打包计算哈希，文件SHA另列。

## 4 优化过程与真实纠错

| 问题 / 优化前 | 优化后 / 可支持的结论 |
|---|---|
| 24位残差先夹紧再乘增益；中间量大于满幅便损失信息 | 25位宽残差先增益、后夹紧；保留旧诊断列，实际播放核对改用宽差 |
| 模型与驱动文件名正确仍可能混搭 | driver拒绝不匹配bit/HWH；C再校十项载荷与模型/Q20身份 |
| 仅查看捕获尾窗便推断整段电平/收益 | 按全局帧号与源结束帧求交集；整窗与共同含源窗分列 |
| Hann FFT未按相干增益归一化 | 峰值除sum(w)；已知0.25FS单音约-12.0412dBFS；RMS另列 |
| 把系数数值范围±8当PCM满幅 | PCM满幅为2^23；用高响应频带单音反例检查预测饱和界 |

宽残差回归的手算例：A仿真用h0=-1.5、麦端8000000、预测-6000000，宽差14000000，增益0.5后应播放7000000。旧路径先夹到8388607，增益后约4194304，已改变波形。新路径恢复这一数值关系；增益1.0导致实际输出越界时仍须限幅并报告保护。[3]

旧现场事件记录的宽残差约1.0230倍满幅，增益后约0.4074倍满幅。该事件支持检查提前截断问题；仅凭预测未饱和或短窗仍不足以排除声学再生，不据此否定其他原因。[3]

## 5 固定单频结果与窗口复核

采用既有round_id=1746930178556850644。三臂具有同一板载PCM SHA、同一模型及fixture、Codec40；open增益0，bypass与cancel增益Q12=1631，仅切旁路。原捕获各16384帧，区间[91037,107421)，板载源结束帧为97656。共同含源区间为[91037,97656)，6619帧，约135.56 ms；完整波形不能覆盖从开始到结束的全部运行。

峰值等效dBFS由Hann加权正弦/余弦及直流拟合得到；功率/RMS另列。对三臂共同有效窗计算，不把源停尾段混入。原JSON保留整窗FFT数字供追溯；两种方法与窗口不能交换使用。

## 6 板上记录、验证范围与限制

A的v3工程证据记录driver79c4d9f7的混搭拒绝、静默检查、输入满幅停声恢复和零系数约60秒运行。持续运行记录为2929687/2929687帧、bit22=0、四类饱和计数0及bit_exact。末窗数字核对与全程状态计数的覆盖范围各自保留；不能将尾窗静音或无饱和推成全程声音质量合格。[3]

真人短时使用和手机受控复现属于不同对象、距离及条件。历史“能听出放大”支持普通扩声的定性观察；另有“听不出差别”的候选对照原话，也应保留。它们不自动互相覆盖。自听掩蔽只是可能解释，重复真人讲话波形不同，麦RMS差不能当相同输入的算法收益。[5]

## 8 从零复现与提交核验

1. 准备Python3.12、NumPy，以及固定输入提交。运行C的assemble_candidate.py向新目录导出；每文件来源、哈希、依赖及排除理由在integration.json。原目录不被覆盖，不需要合并main。
2. 在候选目录运行verify_candidate.py，核十项v3载荷与模型file/Q20/fixture。运行Skill列出的数值/窗口用例；这些步骤无板卡访问。具体命令、退出码与输出在C的validation.json。
3. FPGA重建使用Vivado2018.3、PYNQ-Z2板级文件与已有Tcl/XDC。命令为vivado -mode batch -source build/scripts/create_audio_replay.tcl -tclargs build。保留2018.3是为了沿用已验证依赖；指南允许其他版本但要求报告说明与可复现脚本。此次C未重新综合。
4. FIR测试先运行python scripts/make_fir_vectors.py生成tmp/fir_vectors，再运行build/scripts/test_feedback_fir.tcl。I2S综合使用原厂VHDL；Icarus仿真替身不能当原厂RTL或硬件验收。
5. 板上操作只交A：核v3整套、Codec与fixture、模型和增益；沿用已有有界入口及停止恢复流程。最终入口需A清单确认；本稿不授权或触发声音，不要求复跑已过硬件项目。
6. 清单确认后导出真正RAR并独立解压、重新核哈希和必要用例；同时做匿名、格式、尺寸和许可检查。无RAR工具时只交已检目录，不将ZIP改后缀。
