# 拍摄操作单（一次现场窗口）

目标：一次把 `video-plan.md` 第 5 节的 a01–a06 全部拍齐，**不让任何人按小步骤往返等待**。
预计 **50 分钟**（含 10 分钟布景、10 分钟检查）。所有命令在本机 `_a_work/` 下执行；
板卡 `xilinx@192.168.2.99`，脚本用 `board_run.py <脚本> --sudo` 运行。

先读三条硬规矩：

1. **不改已验证条件**：夹具、麦–音响 100 cm 侧对、增益 −8 dB、Codec 40、位流 `48e38f78…`、驱动 `79c4d9f7…`。
   拍摄不放宽门禁、不改增益、不移动麦克风或音响本体。
2. **不后配现场声**：真人段的原声就用拍摄时录到的；两臂之间不分别归一化响度；不后配啸叫。
3. **标注必须准**：零系数 = 普通扩声（不是算法收益）；候选 = 抵消；手机 = 受控重复声源。
   没有拍到的东西不补拍冒充，用已注明日期的实测图。

---

## 0. 布景与设备（10 分钟）

| 设备 | 角色 | 设置 |
|---|---|---|
| 手机 1 | **主机位**，固定广角，横屏 1080p | 距桌 1.5–2 m，略高，能同时看到人和音响；录原声；开免打扰 |
| 手机 2 | 听众位录音/备机 | 距音响约 20 cm 的听众位置，全程不移动；若 AGC/降噪无法关闭，**记录该限制**，且不用它量化 dB |
| 手机 3 | 特写/备机 | 拍板卡正面、接线；做受控对照时可改为声源，**角色变更要记入 takes.md** |
| 平板 | 提词/说明画面 | 显示作品名与当前段标签；**手动改字不是遥测**，不得当作实时状态 |
| 懒人支架 | 备机或特写 | 先拍 10 秒看抖动；明显抖则只给特写用，主机位换硬支架 |
| 台灯 | 侧上方补光 | 先拍 10 秒查频闪/反光/阴影；50 Hz 照明下先试 25 fps 并逐帧确认 |

拍摄前 3 项检查（各 10 秒素材，算作 a04 的附带素材）：

1. 主机位空镜：看画面是否横平、四个角是否都进画面；
2. 台灯开着拍板卡：看屏幕条纹与金属反光；
3. 关掉房间其它声源（风扇可留但要记）、手机免打扰、平板静音。

## 1. 镜头清单与命令

> 每条命令前都要先跑对应的 `prep_*`（它写操作者确认令牌；脚本只消费、不生成）。
> 预期输出里只要出现 `stop=input_clip` 或 `bit22=1`，该条即判失败，按 §3 处理。

### a01 整体装配与连接全貌（10–15 秒 + 照片）

手机 1 从侧面慢摇一圈：桌面 → 板卡 → 音响 → 麦克风 → 人站位。手机 3 补 3–4 张照片。
**不需要跑板卡。** 照片存 `materials/raw/a01_*.jpg`。

### a02 真人使用主段（关键，45–60 秒）

内容：**系统静音 → 扩声开启 → 系统静音**，一镜到底，真人自然说话。

```powershell
# 1) 写确认令牌并选 a02 模式（20 秒零系数单段）
python -X utf8 board_run.py "wt-a\board\audio_replay\prep_demo_a02.sh"
# 2) 开跑（起飞即静音，跑到 20 秒自动停声并静音）
python -X utf8 board_run.py "wt-a\board\audio_replay\demo_take_v3.sh" --sudo
```

- 说话内容（同一句，自然语速）：「现在进行声堤语音扩声演示，请听清楚这句话。」
  可以连续说 3–4 遍，但**不要喊**。
- 站位：**麦克风前约 20 cm**（已验证合格的位置；不要照搬手机的 5 cm）。
- 台词与动作：开跑后屏幕会打印 `CUE arm a02`（通路已开）→ 立刻开始说；
  看到 `CUE muted again` 就停。整段约 22 秒，录像可以多录前后各 5 秒。
- 预期输出：`DEMO_RUN a02 stop=completed … bit22=0`。**peak 必须 < −6 dBFS**。
- 若 `stop=input_clip`：本次作废，**后退 5 cm 再来一次**（最多 2 次）；仍失败按 §3 走。
- 这条**只展示使用效果**，不用它给算法打分；零系数要在字幕标“普通扩声（零系数）”。

### a03 有效抵消对照（按既有有界流程）

同一几何、同一增益，只改抵消配置。拍两段，画面里保持机位与音响音量不变：

```powershell
# 3) 322 Hz 三点（开/旁路/抵消），板子自己放音，不用人说话
python -X utf8 board_run.py "wt-a\board\audio_replay\prep_ac_tone.sh"
python -X utf8 board_run.py "wt-a\board\audio_replay\field_ac_segments_v3.sh" --sudo
# 4) 屏幕上出三个数（CD / 环路提升 / 声学差），录这一屏
python -X utf8 board_run.py "wt-a\board\audio_replay\tone_analyze.sh" --sudo
```

- 字幕必须写清：**测试信号 322 Hz、数字增益 −8 dB、同一轮次、统计窗口为源激活帧**；
  数字以 C 定稿为准（当前源激活口径：CD 8.46 / 环路提升 3.70 / 声学差 4.95 dB）。
- **不能**声称“听得出变大/变小”：实测两臂播放电平差小于同条件抖动，视频只放测量与波形。
- 若时间允许，再录一段 `field_stationary_v3.sh`（同内容噪声两臂各 2 秒）作为“同源两臂”画面。

### a04 板卡正面与接线（每个 8–10 秒 + 照片）

手机 3 拍：板卡正面全景、LINE_IN 接口、HP+MIC 接口、电源与网线、麦克风与音响到板卡的完整线路径。
**每个角度一张照片**，存 `materials/raw/a04_*.jpg`（最终交 4 张以内）。
不需要跑板卡；若已有 overlay 在跑，不要中途拔线。

### a05 连续运行（60 秒以内）

```powershell
# 5) 60 秒连续运行（零系数），用于“连续性”画面
python -X utf8 board_run.py "wt-a\board\audio_replay\prep_demo_a05.sh"
python -X utf8 board_run.py "wt-a\board\audio_replay\demo_take_v3.sh" --sudo
```

- 这 60 秒可以让手机 3 作为**受控重复声源**（放在 5 cm、音量 6/15），字幕标“手机声源”；
  或保持安静只拍运行状态与进度。两种都要标注真实配置。
- 预期：`stop=completed`、`bit22=0`、四类计数 0。失败保留为失败素材。

### a06 正常停止与软件状态（10 秒）

手机 3 拍 `status.json` 落盘与终端摘要（`DEMO_SUMMARY`/`LONG60` 行），**不需要**专门拍饱和触发。
屏幕上出现的学校名、账号、私人路径要裁掉或遮挡。

## 2. 同步与命名

- 每条开始前**口播编号**（“a02 第一次”），不要靠近麦克风拍手——拍手会制造输入满幅并触发停声。
- 录像文件名：`materials/raw/a02_take01.mp4`、`a03_tone.mp4`、`a04_01.mp4` … 照片 `a04_01.jpg`。
- 板卡侧文件：`ac_*.npz`、`demo_*.npz`、`long60_*.npz` 及其 `.status.json` 留在板卡，
  事后按需取回放 `materials/raw/board/`（npz 不进 Git）。

## 3. 失败出口（照这个走，不要连续试到深夜）

| 现象 | 处理 |
|---|---|
| 门禁 `GATE_FAIL`（峰值 > −6 dBFS 或 bit22=1） | 房间静音 5 秒重跑；仍失败后退 5 cm，最多 2 次 |
| a02 `stop=input_clip` | 本次作废，保留文件与 `status.json`；退 5 cm 重拍；两次仍失败就改用 20 cm 静止段 + 字幕说明 |
| 候选段任何保护触发 | 保留失败原件，**不得**剪成成功；a03 改用已有实测图并注明日期/版本 |
| 板卡无响应或 overlay 报错 | 先 `verify_delivered_v3.sh` 查身份；仍异常则停止拍摄，保存现象 |
| 时间不够 | 优先保 a02 与 a04；a03/a05 可用既有实测记录替代，但必须标注日期与版本 |

**停止方法**：所有试次都有固定预算（a02 20 s、a05 60 s），到点自动停声并静音 Codec。
需要提前中断时，在运行命令的窗口 `Ctrl-C`；驱动的收尾路径会写 `control=0`、静音并恢复 stock overlay。
**不要直接断电**。

## 4. 拍摄后 10 分钟检查（当场做，别带回电脑再说）

1. 每个编号都有文件、时长对得上（`ffprobe -show_entries format=duration`）；
2. a02 的原声里能分辨“静音 → 有扩声 → 静音”；
3. 主机位没有明显抖动、没有频闪条纹；
4. 板卡输出里 `bit22=0`、`stop=completed` 与拍摄记录一致；
5. 把结果填进 [takes.md](takes.md)（文件名、实际配置、版本、结果路径、可引用结论）。
