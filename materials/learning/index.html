先给你一句结论，后面全部在解释它

普通扩声的上限是　g < 1|H|max；　 抵消把它换成了　g < 1|H − Ĥ|max

左边那个 H 是"空气把音响的声音送回麦克风"的本事，右边那个 Ĥ 是我们对它的估计。也就是说：这个作品的本质，是把一个"扩声"问题改写成了一个"建模"问题。扩声的天花板本来由房间决定，改写之后由"我们估得准不准"决定——这是我们唯一能动手的地方。

1啸叫是怎么长出来的

一句话：麦克风不只收到你，还收到"刚才放出来的自己"；这一份被放大后又放出去，每一圈都乘同一个大于 1 的数，于是指数增长。

1.1 先把环路画出来

把设备摆好：麦克风、功放、音响。你说话，声音进麦克风，功放把它放大 g 倍，音响放出来。到这里一切正常。

问题出在下一步：音响放出来的声音，会绕一圈回到麦克风。空气不会分辨"这是人说的还是音响放的"，它照样收。于是麦克风里的信号变成两件事的和：

m = H · u + s

这里 u 是"音响实际放出去的东西"，H 是"从音响到麦克风这一路上，声音被衰减/延迟/染色的总效果"，s 是你真正想放大的那部分（人声直达）。H 就是声学反馈通路。

而 u 又是拿 m 乘出来的：u = g · m。把两式代进去：

u = g(H·u + s)　⟹　u = g · s1 − g·H

分母 g·H 就叫环路增益。它是这一整页唯一真正重要的量。

分母 → 0 时，输出 → ∞。这不是"放大器坏了"，是正反馈：系统在用自己的输出喂自己。数学上这叫"闭环极点跑到单位圆外"，工程上你听到的就是啸叫。

1.2 为什么是"指数"，不是"慢慢变响"

把环路想成一圈一圈走。每一圈，信号乘上 |g·H|。走 n 圈之后是 |g·H|n 倍：

  • |g·H| = 0.9：走 60 圈剩 0.960 ≈ 0.002，听不见。你只会觉得"有点余音"。
  • |g·H| = 1.0：走多少圈都一样大，一直振着。这就是临界。
  • |g·H| = 1.1：走 60 圈变 1.160 ≈ 304 倍，也就是 +50 dB。

而"一圈"要多久？就是声音从音响出发、绕到麦克风、再被处理、再放出去的时间。我们的环路总延迟约 184 帧 ≈ 3.77 ms（这个数字后面 §3 会算给你看）。所以 60 圈只要 0.23 秒。这就是为什么啸叫"突然就来了"——它不是渐变，是指数。

1.3 所以"把音量开大一点"为什么不行

普通扩声只有 g 一个旋钮。要更响 → g 大 → 环路增益大 → 啸叫。于是可用增益被"最敏感的那一个频率"锁死：

g < 1|H|max

我们这套夹具实测 |H| 的峰值是 +4.40 dB @ 321.9 Hz（线性 1.66 倍）。代进去：g < 0.60，也就是 −4.40 dB。

换句话说：不装任何东西时，这台设备最多只能把声音放大到 −4.40 dB——比原声还小 4.4 dB。

这就解释了现场那句"音响不如音源响"：它不是设备不行，是物理上不允许。你要么接受比原声小，要么让环路增益降下来。

如果你只想要"更响"，理论上有两条路：换更好的扬声器/摆位（提高效率，不改环路），或者让环路增益降下来（这条就是本作品）。

2抵消改变了什么

一句话：不装模型时，稳定性由 |H| 决定；装了模型后，稳定性由 |H − Ĥ| 决定。前者是房间给的，后者是我们能改的。

2.1 少减一样东西

思路很朴素：既然啸叫是"回传的那一份"造成的，那就把回传的那一份算出来，从麦克风信号里减掉再放大。

问题是：回传的那一份没法直接测。麦克风里混着人声和回传，它不告诉你是哪一份。但有一个东西我们知道——音响刚才放了什么。软件里播放的每一个采样都是明明白白的。所以：

p[n] = Σ h[k] · u[n−1−k]　　（用过去的播放值预测"它绕回来会变成什么"）
w[n] = m[n] − p[n]　　（残差：减掉预测之后剩下的）
u[n] = sat( s[n] + g · w[n−2] )　　（把残差放大，播出去）

注意最后一步：放大的是残差，不是麦克风原信号。这就是"抵消"和"普通扩声"的全部区别。普通扩声放的是 m，我们放的是 m − p。

2.2 关键的一步代数

设 Ĥ 是我们的模型（h[k] 那串系数就是它）。把三式串起来，只关心"环路"这一圈：

u = s + g(H·u − Ĥ·u)　⟹　u = s1 − g(H − Ĥ)

和 §1 的式子对比一下，唯一变化是分母里的 H 变成了 (H − Ĥ)。整个作品的立足点就在这一处替换。

情形环路增益含义
不装模型（Ĥ = 0）g·H由房间决定，我们改不了
模型完全准确（Ĥ = H）0理论上可以无限放大
模型有误差g·(H − Ĥ)误差越小，能用的 g 越大

第二行是教科书结论，也是很多宣传里"消除啸叫"的来源。但第三行才是现实：误差永远不会恰好为零，所以我们从来不说"消除"，只说"把裕度提高"。

2.3 用滑杆自己验证这件事

回到演示 1。做三个实验，各花 20 秒：

  1. 只开环路：抵消滑杆放到 0，g 从 −8 dB 慢慢推到 0 dB。你会看到曲线从"平"变成"爬"。在 −4.4 dB 附近它开始爬——这就是 §1.3 说的物理上限。
  2. 开抵消，模型准：抵消放到 1，模型幅度误差 100%（误差 0 就是完美模型）、相位误差 0。再把 g 推到 0 dB：曲线会明显低很多，而且不爬。注意：这个演示里"完美模型"是可以设出来的，现实里做不到。
  3. 只把相位调错：模型幅度保持准确，只把相位误差推到 40°。注意 g 一点没变，你会看到抵消效果立刻下降一大截。这就是为什么我们的模型必须"延迟对到帧"——延迟错一点，等于相位错很多。

别把这里的数字当结论。演示用的是"单频 + 三段简化"的模型，真实系统是宽带、有量化、有保护、有饱和。它只能用来看"趋势对不对"，不能推出任何实际 dB 值。所有实际数字见 §7–§10，且都标了口径。

3真实信号流

一句话：一帧 = 2048 个时钟 = 20.48 µs；FIR 用 1539 拍算完预测；残差要等到两帧之后才变成新的播放值；而声音从音响绕回麦克风要 184 帧。

3.1 一帧是什么

音频不像文件那样"整段处理"，它是一帧一帧流过去的。我们的 I2S 每帧左右各一个 24 位采样，采样率 48828.125 Hz，所以一帧 20.48 µs。FPGA 跑 100 MHz，一帧正好 2048 个时钟。

2048 clk ÷ 100 MHz = 20.48 µs　⟹　fs = 1 / 20.48 µs = 48828.125 Hz

这 2048 拍是每帧的全部预算。FIR 要在这 2048 拍里算完，否则就来不及送出去。这条约束后面会决定"最多能做多少抽头"。

3.2 完整的一条路

3.3 三个容易记错的细节

① 参考必须是"实际播出去的"，不是"本来想播的"

FIR 的输入 u 必须是 DAC 真正收到的值，包括增益、包括钳位。如果用"没乘增益的源信号"去当参考，模型学到的就不是真实通路，误差会系统性地偏。这一条写在契约里，是硬约束。

② lag_first = 1：最新一个抽头对的是"上一帧"

RTL 里的写法是：计算开始时把读指针放在刚写进去的那个位置之前，然后递减。所以第 k 个抽头乘的是 u[n−1−k]：

p[n] = h[0]·u[n−1] + h[1]·u[n−2] + … + h[511]·u[n−512]

而"当前这一帧的 u[n]"是算完才写进历史的——不是为了省事，是为了"最老那个样本还没被覆盖时，计算已经完成"。顺序写反了，512 抽头会自己吃掉自己。

③ 两帧调度：算得出来，但赶不上这一帧

FIR 在一帧内就出结果（1539 拍 < 2048 拍），但结果还要经过"乘增益、寄存、等下一次帧边界装进混音"。一次帧边界不够，要两次：

u[n] = sat( s[n] + sat( round12( g · w[n−2] ) ) )

这里的 "−2" 很容易写错。曾经有一版文档把调度写成 1 帧，导致所有"环路延迟"的推算都少 20 µs，进而把"起振频点间隔"算错。凡是写延迟，一律以契约里的这条式子为准，不要从代码注释反推。

3.4 PS 和 PL 谁干什么

角色负责不负责
PL（FPGA）逐样本：FIR 预测、残差相减、乘增益、钳位、混音、I2S 收发、饱和计数不知道"这次实验是什么"，不做决策
PS（ARM）装系数、配增益和帧数、读状态字、把捕获缓冲落盘、决定何时停不碰逐样本运算，不实时干预

这样分的好处是：实时路径上没有操作系统、没有调度抖动，最坏情况由时序分析保证；而"要跑多久、用什么系数、什么时候停"这些慢逻辑放在 Linux 侧，改起来不用重新综合。

4FIR 与 512 抽头

一句话：FIR 就是"把过去若干帧按权重加起来"，3 个抽头能手算，512 个抽头就必须排队一个一个乘——于是有了 1539 拍的预算问题。

4.1 先用 3 个抽头把它算完

取一组能心算的系数（这组是教学用的，不是我们的模型）：

h = [ +0.5,　−0.25,　+0.125 ]

那么：

p[n] = 0.5·u[n−1] − 0.25·u[n−2] + 0.125·u[n−3]

假设过去三帧的播放值是 u[n−1] = 0.8、u[n−2] = −0.4、u[n−3] = 0.2，那么：

0.5×0.8 = +0.400　　(−0.25)×(−0.4) = +0.100　　(0.125)×0.2 = +0.025
累加 = 0.400 + 0.100 + 0.025 = 0.525

如果这一帧麦克风读到 m = 0.600，那么残差 w = 0.600 − 0.525 = 0.075。也就是说：模型认为"这 0.525 里大部分是我自己放出去绕回来的"，减完之后只剩 0.075 是"新东西"。

B. 512 抽头：为什么必须排队

硬件只有一个乘法器（我们只用了 3 个 DSP，其中 1 个就是这个乘），所以 512 个抽头只能一个一个乘。 每个抽头分三拍：读存储器 → 乘法 → 累加。512 个抽头就是 3×512 = 1536 拍，加收尾 3 拍 = 1539 拍。

一帧 2048 拍的时间预算（横轴固定 0…2048 拍）。剩下的 509 拍留给混音、I2S、状态更新。

681 是"每帧算得完"的上限，不是芯片容量上限。FIR 的系数和历史各是 512×24 位，才 24.6 kbit，装两个块 RAM 都用不满；板上 BRAM 报到 80%，主要来自播放缓冲和捕获缓冲。这两件事混在一起说过，是个真实的错误，见 §8。

4.2 为什么是 512，不是 256 也不是 1024

抽头数 = 能记住多久的过去。每抽头 1 帧，512 抽头 = 512 帧 = 10.5 ms。但这里面有一部分是"白花"的：

项时长用途
声学纯延迟184 帧 ≈ 3.77 ms声音真的要走这段路，必须留出位置
可用拖尾记忆328 帧 ≈ 6.72 ms房间混响、桌面反射——这才是模型真正要学的东西

所以"512 抽头"听上去有 10.5 ms，实际只有 6.7 ms 在记混响。这也解释了一个反直觉的现象：64 或 128 抽头完全无效——不是"记得少"，而是根本够不到直达声（184 帧之后才开始有信号）。

那为什么不干脆 1024 或 2048？因为 3×1024+3 = 3075 拍 > 2048，一帧算不完。要做得先改架构（加乘法器并行度，或降低每抽头周期数），那是"换设计"，不是"改参数"。这条线我们明确没走（§9）。

实测告诉我们：从 512 加到 680（还能算完）只多 0.6~0.7 dB。也就是说在这个夹具上，"加抽头"这条路的天花板很低。真正缺的不是记忆长度，而是模型对不对（§6、§8）。

5定点数：Q20 与宽残差

一句话：PCM 的满幅是 ±1.0，系数的满幅是 ±8.0，这两个 8 不是同一个东西；把"残差"在乘增益之前就钳到 1.0，会让系统在明明还有 7.8 dB 余量的时候停声。

5.1 三个数制，先分清

东西位宽/格式满幅怎么换算成"数"
PCM 采样（麦克风、播放、残差）24 位有符号±1.0码值 ÷ 223；范围 −223 … +223−1
FIR 系数24 位有符号，Q20±8.0码值 ÷ 220；所以 24 位能表示到 ±8，不是 ±1
数字增益16 位无符号，Q4.128.0（+18.06 dB）码值 ÷ 4096

把"系数的 ±8"当成"信号的 ±8"去算饱和，是一个真实发生过的错误（§8.5）。判断"会不会饱和"时，永远先问一句：这个 8 指的是哪一个？

5.2 一次预测在硬件里具体怎么做

  1. 乘：24 位系数 × 24 位样本 = 48 位乘积，符号扩展到 58 位。
  2. 累加：512 个乘积相加，仍然在 58 位里。为什么够？最坏 |累加| ≤ 512 × 223 × 8 × 220，远小于 257。
  3. 舍入（Q20 → 整数）：取绝对值、加 219、右移 20 位，再还原符号。加半个 LSB 再截断 = 四舍五入，且负数也远离零。
  4. 饱和：结果超出 ±223 就夹到边界，同时置一个"预测饱和"标志。
round20(x) = sign(x) · ⌊ (|x| + 219) / 220 ⌋

为什么非要"取绝对值再加"？因为 Python 的 >> 对负数是向下取整：−1.5 会变成 −2 而不是 −1，半值方向就不对称了。硬件里没有这个问题，但我们用 Python 复现时必须照着硬件的写法写，否则离线验证和板上永远差 1 个 LSB，而且只在负数半值上差——极难查。

5.3 残差：为什么要 25 位

残差是 m − p。这两个量各自都可能接近满幅：麦克风可以被喊到削顶，预测也可以很大。两个各接近 ±1.0 的数相减，结果可以到 ±2.0。所以硬件用 25 位算这个差：

w[n] = m[n] − p[n]　∈　[−224, 224)

5.4 旧做法错在哪：钳得太早

旧版本（v2）拿到这个 25 位的差，立刻钳到 24 位，然后才乘数字增益。看起来没问题——反正后面还要乘 0.4，先钳应该没关系？

关系很大。因为"能不能钳"要看最终输出会不会溢出，而不是中间量。举个实例：

量v2（先钳后乘）v3（先乘后钳）
25 位宽残差 w1.0230 × 满幅1.0230 × 满幅
乘 −8 dB 之后0.4074 × 满幅0.4074 × 满幅
中间是否越界是（1.023 > 1.0），钳断是，但保留
最终输出0.398 × 满幅（被削过）0.4074 × 满幅（原值）
驱动行为记一次饱和 → 停声只计数 → 继续跑完

注意最后一行：差别不是"音质差 0.2 dB"，而是"整轮实验作废"。v2 把一次"中间量过线但输出只有 0.41、还有 7.8 dB 余量"的情况，当成了危险，直接停。

6标定：系数从哪来

一句话：开环放一段已知的信号，同时记下"放了什么"和"收到了什么"，解一个最小二乘；换摆位就得重来，因为 H 变了。

6.1 六步

  1. 断环：让播放的信号不进入回路（零系数、开环），这样"收到的"里面只有"放出去的"这一个来源。
  2. 激励：放一段白噪声，6 段、每段 16384 帧，段间停一下重起。必须是宽带的，否则某些频率根本没被激发。
  3. 对齐：把每段的"参考 → 麦克风"延迟算出来。这一步不能省，见 §8.2。
  4. 拟合：解 H 的 512 个抽头。用最小二乘（带一点点 ridge 正则，防止病态）。
  5. 验证：留出段只评一次。同一场次的交叉验证不算"新场验证"。
  6. 量化与装载：浮点系数 → Q20 整数 → 写进模型文件 → 核 SHA256 → 装到板。

6.2 为什么是"离线拟合 + 固定系数"，而不是 LMS

教科书里反馈抵消最常用的方法是自适应滤波（NLMS 一族）：边跑边更新系数。听起来更聪明，但在闭环里有一个致命问题：

自适应算法需要"干净的参考"——也就是"如果没有任何反馈，信号本来该是什么样"。可在闭环里，播放信号本身就含反馈分量，参考不干净。于是算法会把"反馈"也当成"要学的通路"，解发生偏移（bias）。学得越久，偏得越远。

所以要让它稳定工作，得额外加去相关手段（延迟、频移、预白化……），每一样都会降低音质或增加复杂度。我们选择了另一条路：

离线标定 + 固定系数（我们）在线自适应（LMS/NLMS，未做）
适合场景摆位固定（本作品的前提）摆位会变
闭环偏移不存在（断环下标的）存在，需要额外手段
换房间必须重标理论上自己收敛
算力标定在 PC 上，板上只做固定 FIR板上要留更新通路和稳定判据

"必须重标"不是缺点，是前提。正因为我们接受"位置固定"这个前提，才能用最省算力、最可预测的方式工作。简介里那句"面向麦克风与扬声器位置相对固定的语音扩声场景"，说的就是这件事。

6.3 场景一变，模型就废：一个真实例子

2026-10-26 我们换了摆位（音响离麦克风 100 cm、侧对、上方加了金属板），但板上装的还是按旧摆位（0.5 m 正对）拟合的系数。用新采的数据一算，结果很难看：

旧系数在新摆位上"反向工作"

在 325 Hz 处，CD = −4.27 dB。CD 是"抵消深度"，负值意味着残差比原信号还大——模型不是没帮上忙，是在放大。

原因
旧系数是按 124/125 帧的路径延迟拟合的，新摆位的路径是 184 帧。滤波器整套比实际路径"早到"约 57 帧（1.2 ms）。
证据
旧系数的冲激响应峰在第 128 抽头，新拟合的在第 184 抽头。
修法
不是平移系数（会砍掉尾部记忆、打散高频），而是按新摆位重拟合。

这个例子最值得记的一点：模型错的时候，它不会"效果差一点"，它会主动帮倒忙。因为它在用一个相位错误的预测去做减法，减掉的是有用信号、加回去的是反馈。

6.4 延迟必须对到"帧"

1 帧在 321.9 Hz 上是多少度？

Δφ = 360° × f / fs = 360° × 321.9 / 48828 ≈ 2.37°

看起来很小。但在 8.4 kHz 上，1 帧就是 62°——足够把"完全抵消"变成"几乎全反"。

更麻烦的是采集本身：同一批六份数据里，有三份的参考延迟是 184 帧、三份是 185 帧。差一帧，跨段累加时高频就全错。所以脚本里第一步永远是"逐段对齐到同一个整数延迟"，然后再做统计。

8真实失败与弃选

一句话：这一节是整页最值钱的部分。七个坑，每一个都让我们白跑了一轮现场。

失败 1 · 用"没叫"当"抑制成功"

发生了什么：早期很多轮实验的结论是"某档稳定、没啸叫"。但同一批数据里出现过：播放电平完全没变，麦克风却从 −29.8 dBFS 掉到 −64.3 dBFS。

原因：有源音响会待机。它一待机，环路就断了，"稳定"是假的——不是系统抑制住了，是回路根本不存在。

教训："没有发生 X"这种负向观测，在底噪上分不清"稳定"和"回路断了"。所以现在每一轮现场测量的第一步必须是正向对照：直放一段、确认麦克风电平在基线内，否则后面所有"稳定"都不算数。

同一次错误还导致过一个数值被反推出来（β = 0.395），以及所有由它派生的结论（CD −3.64、512 更差、重标定 +13.5 dB）——全部作废。

失败 2 · 参考对齐差一帧，抑制从 −9 dB 掉到 −0.3 dB

发生了什么：同一批房间数据里，前两段的参考延迟是 124 帧，其余是 125 帧。跨段累加统计时没有先对齐，结果是"抑制只有 −0.3 dB"。

原因：差一帧 = 在高频上差几十度相位。相位一错，残差就不是"小"，而是"随机"，统计上等于没抵消。

现在的做法：脚本第一步永远逐段估计延迟并平移对齐；静音段（麦克风比底噪低 20 dB 以上）直接剔除，不能进统计。

失败 3 · 把"停源后的尾窗"当成有效段

发生了什么：捕获窗口里最后一段源已经停了（我们的采集里每份 16384 帧，源只覆盖前 15407 帧）。有人把整窗都算进残差统计，于是"抑制"变了——因为尾段里根本没有"要抑制的信号"。

原因：统计窗口混进了没有信号的部分，分子分母都不是原来那个意思了。偏大还是偏小取决于底噪与残差底谁更高，但无论偏哪边，这个数都不再代表抵消效果。

现在的做法：统计只用源仍然有信号的帧；尾段单独判。判据要逐条查：源已停 ≥40 dB、距最后有源帧 ≥512、麦克风高于底噪 ≥10 dB、不削顶、≥2048 帧、元数据一致。

发生了什么：有人算出"带内平均耦合约 −11 dB"，于是写"环路增益 = −8 + (−11) = −19 dB，远低于 1，所以正增益可行"。

错在哪：−11 dB 是能量平均，而稳定性由峰值决定。同一份数据里，峰值是 +4.40 dB @ 321.9 Hz。两者差 15.4 dB。

后果：0 dB 时环路增益其实是 +4.40 dB，必然啸叫。这跟现场实测一致（0 dB 满幅啸叫）。如果按 −19 dB 去排实验，那一轮会直接炸掉。

失败 5 · 把"系数满幅 ±8"当成"信号满幅 ±1"

发生了什么：为了证明"模型不会撑爆 24 位"，算出"|pred| ≤ ‖h‖₁ × 满幅 = 2.29，离饱和阈值 8.0 还差 10.9 dB，所以不会饱和"。

错在哪：8.0 是系数的 Q20 满量程，不是 PCM 的满量程。PCM 侧饱和阈值是 1.0。所以正确的说法是"‖h‖₁ = 2.29 > 1，存在合法输入让它饱和"。

后果：差 18 dB 的判断。如果现场因为这句话把保护当噪音关掉，会出真问题。已撤回，并在回归测试里钉住"两个 8 不许混"。

失败 6 · 白噪声分带占比当仪器，符号会翻

发生了什么：想用"300–360 Hz 能量占比"比较零系数臂和候选臂。三次重复给出 +1.6 / −4.7 / −2.1 dB——连正负都不一致。

原因：白噪声在这个夹具里耦合太弱（输入从 −20 到 −6 dBFS，麦克风峰峰值只涨 3.5 dB）。两臂都坐在房间底噪上，比的其实是底噪起伏。

现在的做法：改用|H| 峰值处的纯音（322 Hz）：所有能量集中在一个 bin，比底噪高约 40 dB，读数才稳。而且占比是比值，会被总电平差污染——两臂总电平差 7.8 dB 时，占比差和绝对差方向可以相反。

失败 7 · 输入削顶把整轮实验作废（而且和距离无关）

发生了什么：12 cm 讲话时 bit22 = 1（ADC 顶满）。但换到 20 cm 也出现过 bit22 = 1。

意味着什么：削顶不取决于距离，取决于讲话力度。所以"退远一点就安全"是错的，靠移动解决不了。

为什么严重：ADC 一顶满，信息已经丢了，数字侧任何处理都补不回来。所以这类数据整轮判无效，不是"稍微差一点"。

现在的做法：bit22 变成独立检测并自动停声（§5.5）。宁可停，也不要拿削顶的数据下结论。

9没做、不打算这么做

一句话：AFC / 在线 LMS / 自适应 / 多速率都没有实现。它们在报告里只能出现在"未实施"或"后续可选"，不能画进框图，也不能说"已被否定"。

未实施（没有代码、没有上板、没有数据）
  • 在线自适应（LMS / NLMS）：选它的理由和放弃的理由都写在 §6.2。放弃不是因为"做不到"，是因为"在闭环里做会偏移，而且要额外去相关手段"。
  • AFC（自适应反馈控制）作为独立模块：没有实现。我们的"抑制"来自固定模型抵消，不来自自适应估计。
  • 啸叫检测 / 陷波自动触发：没有。这一点很关键：现场零臂啸叫时停声，是麦克风满幅触发 bit22，不是"识别出啸叫"。不要把它讲成"检测到啸叫并保护"。
  • 多速率 / 子带处理：只有仿真，没有 RTL。
  • 换电平后的行为：只在一档注入下标定过，"更响时通路会不会变"仍是未知。

写"未实施"不是示弱。把边界说清楚，别人才敢用你的结论。反过来，把没做的写成做了，一旦被追问细节（"你们的更新率是多少？""双讲怎么处理？"）就崩了。

10指标：别把四种 dB 混着说

一句话：CD 说模型准不准，环路提升说这一带被抬高多少，界差说稳定裕度差多少，ASG 才是"能多开多少增益"——前三个都不能替代第四个。

CD（抵消深度）20log₁₀(|H| / |H − Ĥ|)模型把路径拟合得多准不能。它是中间量
环路提升bypass − open闭环把这个频点抬高了多少能，但它只等于"抵消最多能收回多少"
界差−20log₁₀max|H−Ĥ| 与 −20log₁₀max|H| 之差稳定裕度差多少不能当实测 ASG。是充分条件，可能保守
ASG两臂"起振临界增益"之差（实测）能多开多少增益能。本作品目前还没有
听众可辨人判断到底听不听得出能，但要写清问法和人数

10.1 dBFS 和声压级不是一回事

  • dBFS 是数字域：相对满幅。0 dBFS = 码值顶到 ±223。它不知道你麦克风灵敏度多少、增益多少。
  • dB SPL 是物理声压：20 µPa 为 0 dB。它不知道你的数字链路。

两者之间差一个"灵敏度 + 增益 + 校准"的常数。没有校准就说"我们做到了 60 dB 抑制"是没有意义的——数字域减了 60 dB，可能只是把音量调小了。

10.2 为什么"界"不能直接和"实测"相减

界是充分条件：界说"能开到 0.68 dB"，意思是"开到 0.68 dB 一定不啸叫"，没说"超过就一定叫"。所以：

  • 实测边界 ≥ 界 → 正常（界保守）
  • 实测边界 < 界 → 说明模型或测量有问题，要查

拿"界差 5.08 dB"去当"实测提升 5.08 dB"讲，是最常见的越界。我们只说界差，不说 ASG。

10.3 一个反直觉的发现：提增益换不到响度

从 322 Hz 三点能反推出通路在这个频点的相位：约 ±40°。这意味着 H 不在正实轴上，于是：

played / source = 1 / |1 − g·H|

这个量在 g = −6.7 dB 处见顶 3.87 dB，之后继续提 g 反而下降。而我们在 −8 dB 时已经是 3.75 dB，距离上限只剩 0.12 dB。

所以"音响不如原声响"不是增益不够，是这个环路在 322 Hz 上最多只能放大 3.87 dB。想更响只能动扬声器效率、指向、到听众的距离——那是另一个问题。

11怎么讲、怎么答

一句话：先讲"你只能比原声小 4.4 dB"这个痛点，再讲"我们把判据从 |H| 换成 |H−Ĥ|"，最后老实说"实测 ASG 还没有"。

11.1 三分钟口述稿（约 450 字）

麦克风和音响放在同一个房间里，音响放出来的声音会绕回麦克风，被再放大一次。这形成一个正反馈：每一圈都乘同一个数，一旦这个数大于 1，声音就指数增长——这就是啸叫。

普通扩声只有一个音量旋钮，所以它能开到多大，被"最敏感的那个频率"锁死。我们这套设备测出来，最多只能放大到 −4.4 dB，也就是比原声还小 4.4 dB。这就是"音响永远盖不过人声"的原因。

声堤做的事是：用实际播放的信号，经一个固定的 512 抽头滤波器，预测"它绕回来会变成什么"，然后从麦克风信号里减掉，再放大。数学上，这把稳定条件从 |gH| < 1 换成了 |g(H−Ĥ)| < 1。前者由房间决定，后者由我们模型的准确度决定。

整个系统跑在 PYNQ-Z2 上：FPGA 每 20.48 微秒处理一帧，预测用 1539 个时钟算完；ARM 负责装系数、配增益、读状态、落盘。

现在能给出的硬结论是：单频 322 Hz 上，抵消把闭环 3.75 dB 的抬升收回，残差深度 6.37 dB；稳定裕度的离线界差是 5.08 dB。实测 ASG 和宽带可听收益还没拿到，这是我们下一步要补的。

11.2 十个必被问到的问题

Q1　你们是不是把反馈"消除"了？
不是。我们降低它、把稳定边界往上推。模型永远有误差，所以环路增益只能变小、不能变零。说"消除"是不准确的，也是不必要的承诺。
Q2　为什么不用 LMS 自适应？
闭环里参考信号本身含反馈，自适应会偏移（bias），要额外做去相关。我们选了"离线标定 + 固定系数"，代价是换摆位必须重标——而我们的前提本来就是位置固定。
Q3　换一个房间还能用吗？
不能直接用。H 变了，系数必须重标：放一段白噪声、断环采六段、拟合、验证、装载。我们做过一次换摆位，旧系数在新摆位上 CD 是负的——在放大，不是抵消。
Q4　你们的"抑制"有多少 dB？
分三个数说：单频 322 Hz 的残差深度 6.37 dB、闭环抬升被收回 3.75 dB、稳定裕度的离线界差 5.08 dB。实测 ASG 还没有。三个数不是一个东西，不能挑一个当结论。
Q5　为什么 512 抽头？加更多不行吗？
512 抽头 = 10.5 ms 记忆，扣掉 3.77 ms 声学延迟还剩 6.7 ms 记混响。加到 681 是每帧算得完的上限（3N+3 ≤ 2048），实测只多 0.6~0.7 dB；1024 就超预算，要改架构。
Q6　怎么保证不出事？
五类停声：输入满幅、预测饱和、增益后/混音饱和、协议错误、超时，加手动。输入满幅是独立检测的——零系数时残差恒等于麦克风，用它看不见输入过载。
Q7　你们检测啸叫吗？
不检测。系统是无条件地做抵消，不做"识别啸叫再动作"。现场零臂啸叫时之所以停，是麦克风顶到 ADC 满幅触发的，不是识别出啸叫。
Q8　为什么证明不了"更响"？
两个原因。一，322 Hz 的相位差 40°，played/source 在 −6.7 dB 就封顶 3.87 dB，我们在 −8 dB 已 3.75，只剩 0.12 dB。二，"更响"还要看扬声器效率和到听众的距离，那不是增益能解决的。
Q9　数据可复现吗？
模型带文件哈希与系数哈希，装板后可核对；每条结论都能追到 report/verification/ 下的目录和一条命令。回归里的整数重放与板上 prediction 曾做到逐样本 0 失配（15871 帧）。
Q10　最大的失误是什么？
有两类。一是用语不严：把"宽带平均耦合 −19 dB"当成环路裕量，结论直接反了 15 dB。二是把标签当事实：metadata 写着"开环"，实际是增益 0，我们差点按标签放行；后来改成用"参考是否逐样本等于源"来判。

11.3 三条不要说的话

  • 不要说"完全消除啸叫""任意场景可用""零延迟"。
  • 不要把界差、CD、声学差任何一个说成 ASG。
  • 不要说"检测到啸叫后自动保护"——我们没有啸叫检测。

12术语表与复现

12.1 术语

H
声学反馈通路：从音响到麦克风这一路的衰减、延迟、染色。宽带的，用 512 个抽头近似。
Ĥ
我们拟合出来的 H 的估计，也就是那 512 个系数。
g
数字增益，Q4.12，范围 0…8（+18.06 dB）。现场授权用的是 −14…−6 dB 这一小段。
环路增益
不装模型时是 gH，装了是 g(H−Ĥ)。|·| < 1 才稳。
lag_first
FIR 最新那个抽头对的是 u[n−1]，不是 u[n]。全仓库统一为 1，有回归测试钉住。
Q20
定点小数格式：值 = 码值 / 220。系数用 24 位 Q20，所以能表示到 ±8。
饱和
结果超出可表示范围就夹到边界，并置标志。夹是不得已，标志是为了让上层知道。
宽残差
用 25 位算 m−p，保留到乘完增益再钳到 24 位。v3 的改动。
CD
抵消深度：20log₁₀(|H|/|H−Ĥ|)。负值意味着在放大。
ASG
附加稳定增益：两臂起振临界增益之差。本作品尚未实测。
相干
两个信号在某个频率上的线性相关程度（0…1）。低于 0.8 的频点我们不拿来下结论。
相位穿越
环路相角过 0 且幅度仍够的频率。它决定理论上会在哪里啸叫，但我们在实测数据上用它不稳，故只作参考。
