## 1. 一句话背景

"声堤"要在 PYNQ-Z2 上做声反馈（啸叫）抑制。现有资产是：256 抽头 Q20 定点 FIR、
开环残差已板上逐样本核对通过（预测误差降低 6.92 dB）、闭环最小版已构建并在
约 −36 dB 下做过数字核对。**但没有任何正常扩声条件下的抗啸叫效果证据。**
B 负责用已有数据把"模型到底哪里不准、能多推多少音量"算清楚，给 A 一个可执行的实验范围。

## 2. B 这轮最重要的一个判断（会直接影响 A 的实验设计）

**现有评价口径 `宽带 RMS 预测误差降低 9.8 dB` 不能用来判断效果，甚至会给出相反结论。**

原因是几何关系：啸叫只发生在一个频点，稳定条件也只由那一个最差的频点决定。

```
闭环:  u = G·z^-2·(H - Ĥ)·u + 源          稳定条件 |G·(H-Ĥ)| < 1 对一切 f
MSG_bypass = 1 / max|H|                  （旁路能推到几倍增益才叫）
MSG_cancel = 1 / max|H - Ĥ|              （抵消开启后能推到几倍）
ASG        = max|H| / max|H - Ĥ|         （抵消带来的稳定增益差）
```

`z^-2` 就是顶层 `played[n+2] = gain(residual[n])` 的两帧调度。

合成验证给出的量级对比（**合成，不是实测**）：

| 抽头 | 宽带降低 | 逐频点最差抵消深度 | ASG |
|---:|---:|---:|---:|
| 128 | 5.83 dB | −1.95 dB | 0.90 dB |
| 256 | 12.36 dB | 4.59 dB | 6.18 dB |
| 512 | 14.98 dB | 11.33 dB | 15.12 dB |

抽头 256→512，**宽带只涨 2.6 dB，ASG 涨 8.9 dB**。
所以历史记录里"512 只比 256 多 0.37 dB，保留 256"这个决定，是用一个对目标不敏感的量
做出来的，**在真实数据上必须重算**。

第二个佐证：把**已知真值**的冲激响应截断到 N 抽头，和拟合出来的 N 抽头模型比，
最差频点深度只差 0.15 dB（128/256/512：真值 −1.9/4.5/11.2，拟合 −1.95/4.59/11.33）。
**结论：瓶颈是覆盖长度，不是估计器。换更好的拟合算法没用。**

## 3. 另外三个会影响 A 决策的数字

1. **−36 dB 那批实验在数学上不可能有区分度。** 报告里 `max|h| = 0.52`，旁路临界增益
   至少 1/0.52 = **+5.7 dB**，实际工作区在 0 dB 附近。−36 dB 时环路增益约 0.001，
   旁路和抵消都不可能起振。所以"一次没听到尖叫"和模型好坏完全无关。
   同理，早先计划的 −30/−24/−18/−12 dB 四档整体偏低 30 dB 以上，**不要照着跑**。
2. **硬件增益上限 +18.06 dB**（Q4.12 最大 8 倍）。如果估算说抵消后要 +20 dB 才叫，
   那在现有 bitstream 上就是"推不响"，这是正常结果，不是失败。
3. **架构上限约 680 抽头**（每抽头 3 拍、帧预算 2048 拍 → 3N+3 ≤ 2048）。
   换算成距离：256 抽头 = 5.24 ms = 1.79 m，512 = 3.60 m，680 = 4.8 m。
   小箱体够用；"会议室"场景只要麦克风—音箱超过 2 m 加混响尾就装不下。

## 5. 需要 A 做的只有一件事：把三个文件拷出来

**不需要把板卡给 B，也不需要板卡在线。** B 缺的只是文件：

```
板卡 base/audio/audio_calibrate/ 目录下：
    training_box_v1.npz          ~0.5 MB
    validation_box_v1.npz        ~0.5 MB
    candidate_box_v1_256.json    ~6 KB
```

拷到电脑任意目录，然后在仓库根目录执行一条命令：

```text
python scripts/analyze_path.py --data-dir <目录> --output report/box-v1-analysis.json
```

不用加载 overlay、不用播放、不用采集。跑完给出的就是：
真实箱体的共振峰位置、抵消最差频点、128/256/512 的真实 ASG 对照、
以及**现场该测哪几个增益**。

如果更愿意在板上跑，等价命令是上传 `calibration.py`、`path_analysis.py`、
`path_analysis_box_v1.py` 后 `%run path_analysis_box_v1.py`，输出同一份 JSON。

**关于隐私**：这三个文件不含人声。标定激励是 PL 里的 xorshift 伪随机数自己发的噪声，
录回来的是"噪声穿过箱体"。`docs/` 里"原始录音需授权"那条针对私人内容，这里不适用。

## 7. 给 A 的 AI：不要做的事

1. 不要重跑 −30/−24/−18/−12 dB 那批。它在数学上没有区分度，浪费现场时间。
2. 不要把"抵消时没听到啸叫"当成功。必须在**同一增益**下与旁路成对比较，
   旁路叫、抵消不叫才算证据。
3. 不要为了"更好看"去改 Codec 音量或 PL 增益后仍沿用旧系数——那时 `H` 已变，比较不公平。
4. 不要改 `src/feedback/`、`feedback_fir.v`、`audio_pl_closed.v` 的算法与调度语义。
   这些是 B 的边界；确有需要先提接口变更，避免让 A 加载到不兼容的系数或 bitstream。
5. 不要把本文件第 4 节的合成数字写进竞赛报告当作实测性能。它只说明趋势与量级。

## 9. B 自己踩过、A 的 AI 也别踩的坑

| 坑 | 表现 | 正确做法 |
|---|---|---|
| `lag_first=1` 差一拍 | 把 `room[:256]` 当系数，完美模型的抵消深度算成 −1.6 dB，比空模型还差 | 系数数组是 `room[1:257]`；`pred[n]=Σh[k]u[n−1−k]` |
| 码值重复缩放 | 闭环模拟里 `room` 已作用在 24 位码值上，又乘了一次 2²³ → 任何增益都立刻饱和 | 只对满幅表示的源信号乘 2²³ |
| 频带下界取 60 Hz | 把 20 Hz 以下的环路增益漏掉；合成里出现过 DC 环路增益 1.09 > 1，低频先漂起来 | 下界取 20 Hz，直流单列 `dc_diagnostics` |
| 只看 `saturation>0` 判发散 | 缓慢指数增长被误判成稳定 | 加"后半段分块斜率 > 6 dB/整段"与门 |
| 把合成结果当实测 | — | 本文件所有数字都标了来源；实测仍全部未完成 |
