# A 角色现场交互规范

适用于声堤板卡音频现场试验。操作包、Notebook和现场提示均按本规范编写。

## 开始前一次性交代

用简短说明写清本轮目的、现场准备、预计发声次数/总发声时长、整个流程耗时估计、结束标志和最终应返回的文件。执行后不临时追加下一项试验。

## 文件路径和传输

每个文件都标明电脑本地完整路径、板卡完整路径、上传/新建/覆盖动作、需要保留的旧文件、上传成功标志及下一步入口。区分电脑本地和板卡文件，不能把本地生成表述成已上传。

上传后由AI核对；用户自行上传时，说明核对文件名、哈希或其他确定标志。Jupyter的上传控件若在选中文件后再次显示确认按钮，须点击确认，直到板卡文件列表中出现文件。

## Notebook代码格定位

同时给出代码格编号、标题和代码首行。Notebook左侧的 `In [n]` 是执行计数，不能当成代码格编号。没核实用户版本时，不猜编号，应先核对文件哈希或提供标题/首行。

## 每个操作步骤

每一步都说明：为什么做、在哪里做、具体怎么做、预期发生什么、接下来怎么办。若改参数，提醒重新执行参数代码格，让运行时变量更新。优先提供整段可替换代码，避免让现场人员在长代码中搜索字符。

## 先准备，后发声

代码编写、检查、上传和配置全部完成后，确认设备仍静音，再通知用户准备听或讲话。持续声源优先用位置和音量固定的循环播放。输入框只在试验开始前或结束后工作，不能当作播放中的急停；现场必须有断电办法。

## 批次和结果

一批实验一次交代。提前说明继续条件、停止条件、自动保存内容和最终返回路径。正常情况下用户连续操作，不需每项回聊天等待。已有证据直接复用，不要求重复提交。出错时先判断所处阶段，再给出最短恢复办法，不默认整批重跑。

## 实物试验要求

- A统一控制板卡，B/C代码由A排期运行。
- 明确箱体、麦克风、音响、接线、声源和音量状态。麦克风在箱内时，不得要求现场人员在麦克风旁讲话。
- 一对旁路/抵消试验固定硬件位置、Codec音量、PL增益、声源和时长，只改变指定变量。
- 改夹具或音量时记录变化，并重新评估原模型是否适用。
- 发声前说明每项时长和停止方法。输入框不能代替立即断电。
- 分开报告听感和数字结果。没有尖叫、没有报错和数字匹配分别代表不同证据。
- 基础验收通过后结束该阶段。每个新实验需减少一个关键未知，不能重复低增益、短时间且无区分度的尝试。

每份A交付都让现场人员明确当前操作位置、要做的动作、预期结果、停止/继续条件和要返回的文件。
