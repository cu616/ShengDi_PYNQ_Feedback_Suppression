## 限时低音量直通

前提：驱动确有bypass(seconds)，已核对本机接口与示例；保持已验证接线。音响低音量，麦克风先远离并避开音响正面，不佩戴耳机测试反馈。一名现场人员可立即关闭音响电源；不以浏览器中断键作为唯一停止办法。

```python
import time

audio.select_line_in()
audio.set_volume(10)  # 候选低起点；不是百分比，不是固定安全声压
t0 = time.monotonic()
print('开始短时直通', flush=True)
try:
    audio.bypass(2)
finally:
    audio.deselect_inputs()  # 只有底层调用返回/抛异常后才会执行
print('调用耗时(s):', time.monotonic() - t0)
```

正常情况下约两秒结束；耗时不是音频端到端延迟。若持续尖叫或超过预期仍有声音，立即关闭音响电源，不等待Python清理。确认程序退出后再处理软件状态。每轮需重新select_line_in；set_volume(0)也不是硬静音。

低音量无声时先检查有效输入声道与音响接收声道，恢复已知录放验证，不盲目拉满增益。正常同步扩声、正常结束后，才尝试反馈观察。

## 反馈观察

固定麦克风前级旋钮、音响旋钮、位置、输入声道与程序。只在两次短试验之间小步调整一个输出增益参数；每次短时运行，观察是否有逐渐增强的窄带鸣响。首次出现明显增长即关闭音响，记录条件，不追求持续大声尖叫。到合理工作音量仍未出现，记录未复现，检查环路；不据此认定腔体失败，也不要求继续加大声音。

每轮记录：日期/操作者、Notebook版本、接线/供电、采样率、输入声道、MAX4466旋钮位置、Codec音量参数、音响旋钮位置、距离/朝向、计划时长、实际返回时长、语音同步与否、鸣响趋势、停止是否有效、证据路径。手机录音/视频只作现象证据，不能据其AGC后的音量推算dB增益或绝对声压。

本试验不输出正式MSG或ASG；短时间不叫不能证明长期稳定。公开bypass不把音频写入录音buffer，不能随后save就声称保存了本轮直通音频。不得并发调用record去抢占同一个音频控制器。

## 对历史草案与现计划的修正

1. archive的“录放成功便可拉啸叫”漏掉持续通路验证；顺序record/play不构成实时扩声回路。
2. 不必等自定义PL完成才能做声学预实验。官方bypass可降低实验起步门槛，但不证明自定义PL能力。
3. 公开bypass通过PS端C代码轮询I2S寄存器搬运样本，没有软件等待超时；seconds不是独立硬件截止计时器。最终PL主路需独立静音和错误状态。
4. 正式算法开关比较必须使用同一条最终通路。不能把PS bypass与PL抵消之间的阈值差全部算成算法收益。
5. 低延迟不保证MSG单调提高；单峰不能可靠区分乐音与反馈。三模式/微秒端到端/200ms收敛均不可先当成果。
6. 路径标定必须同步发测试信号与采输入，先play再record会漏掉响应；参考点、模拟增益与延迟必须一致。
7. 固定FIR抵消是建议的首版，但并不自动容易：模型长度、声道、极性、对齐、扬声器非线性和路径变化都可使它失败。
8. 256抽头、64乘法器四拍完成并非完整架构；还缺访存带宽、求和树、流水与系数更新预算。16×24位乘积需40位，256项全精度累加还需保护位，不能默认32位。
9. 盒子不等价助听器；开孔不保证反馈单调变化；固定桌面夹具即可起步。音质、增益、资源与可靠性一起评价，ASG不是唯一指标。
