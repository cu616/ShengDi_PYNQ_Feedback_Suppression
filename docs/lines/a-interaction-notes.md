# A 线的 AI 与人协作习惯

> 用途：记录「AI 与 A（现场唯一操作者）」之间已经磨合出来的配合方式，减少往返和返工。
> 与 [分工与边界](a-field.md) 不同，这里写的是**怎么做**，不是**做什么**。
> 新增条目请写清触发场景，不要写成口号。

## 一、通知与节奏

1. **需要人做动作之前，先一次说清**：要听什么、多久、怎么答、接下来发生什么。
   现场因为"等你半天"已经抱怨过一次；不要让人为一个 10 秒的动作等 5 分钟。
2. **凡是需要人先做动作的提示，绝不能自动代答。** 已发生两次事故：
   - "先暂停手机再 START"被脚本直接回了 START，导致定音期间声源仍在放，正向对照失败；
   - 自动应答"开始说话"类提示，采到的窗口里没有人声。
3. **人不在现场时批量做离线工作**（分析、文档、预处理），**不要用需要现场的步骤把人叫回来**。
4. 一次准备一个完整窗口，不要为每个小步骤往返。

## 二、汇报方式

1. **先给结论，再给证据**；结论用表格，数字带单位。
2. 判断类问题只要**关键词**：`能/不能`、`更大/差不多/更小`、`有/没有`。
   **不要让人写长段描述**；需要原话时明确说"请记一句原话"。
3. 每条结论标明**验证层次**：静态审阅 / 仿真 / 综合 / 上板 / 复现，别混。
4. **撤回要写进记录，而且要显眼**。A 明确要求过：撤回的东西必须能查到，不能被悄悄掩盖。

## 三、判断与异议

1. **人提出异议时，先当成数据，不要先辩解。** 已发生多次人是对的：
   - "听众一直在同一位置" → 位置不是变量；
   - "一直是手机代替真人" → 此前所有"真人"标签错误；
   - "78 cm 不可信" → 我的推断前提不成立，撤回。
2. **不要用"读者会误解"为由模糊结论**；错了就写"这条错了，原因是 X"。
3. **不臆造解释**。分不清就写"未知"并列出能分辨的实验，不要给一个自洽但无证据的故事。
4. 人反复强调的判断（例如"放大了就是放大了"）要保留在记录里，即使当时的数据不支持。

## 四、文档与交付

1. **不要堆文档充数。** 人明确表示过：要的是活干完，不是转发稿写得漂亮。
   转发稿只在**确有队友需要据此行动**时给，且只要最小集。
2. 详细内容进仓库文件，聊天里只给人**能直接粘贴**的那一小段。
3. 一条事实只写一个权威位置，其他地方链接过去。
4. 每次收工：覆盖 `docs/STATE.md` 自己那段 + `docs/log/progress.md` 顶部追加一条 + `check_docs.py` 0 错误 + 提交推送。

## 五、现场操作

1. 先说清**物理动作**（放哪、多远、音量几档、开始说话/播放），再说 AI 要执行的命令。
2. **音响、麦克风、手机位置**每次操作前确认一次；今天松线事故造成了三次无效采集。
3. 输入电平必须先量后跑；**峰值 ≥ −6 dBFS 就停**，不要"先跑了再说"。
4. 现场实验的判据要能落到**一个具体数字或一个具体回答**，否则不要做。

## 六、环境与工具

1. PowerShell 里的 here-string 会破坏内联 `-c` 代码，**一律写文件再执行**。
2. Windows 下 Python 一律加 `-X utf8` 或 `PYTHONUTF8=1`（B 的脚本曾因 `U+2212` 崩）。
3. 上板前先探活：`ping 192.168.2.99`；本轮出现过一次断网。
4. 板卡 helper：`_a_work\board_run.py <脚本> --sudo`，密码走 `$env:SHENGDI_SSH_PASSWORD`。

## 七、今天学到的三条硬经验

1. **读数不随激励变化时，先查接线，再谈声学。**
2. **分次比较频带电平必须用稳态源**；非稳态内容会让指标漂 30 dB 并给出相反结论。
3. **计数器为 0 不等于没发生**：零系数时残差恒等于麦克风，残差计数天生看不见输入过载或再生。
