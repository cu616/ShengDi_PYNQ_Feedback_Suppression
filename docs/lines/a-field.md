## 2. 文件与实现边界

你是唯一板卡操作者，维护底层音频驱动、Codec、MMIO/寄存器访问、I²S、外围硬件顶层、构建与 bit/hwh 集成。B 维护算法核、定点与反馈历史语义；C 维护批次编排、判据、汇总和完整实验包。

## 3. 怎样独立推进和汇合

等待 C 的新包时，完成已明确的本线驱动修复、构建、接线和夹具准备。不要用重复低增益检查填空。拿到 C 的冻结包后，核对兼容性、部署并执行整批；包中应已整合 B 的模型与预测、配置、判据及汇总，A 不再承担三方代码拼装。

实验可包含事前约定的条件分支。只有继续条件满足才执行下一项；缺数据、保护早停、配置变化或未知结果不能自动授权继续升档。每轮固定 bit、模型、驱动、测评器、源与夹具，变更则另起版本。

出现分歧时，A 查硬件与条件，B 查模型假设，C 查测量与复算。依据数据解决；证据不足就暂停依赖该结论的分支，继续其他独立工作。角色不代表对科学结论的最终裁决权。

## 5. 一次现场配合完成一批

操作前在 STATE 的“板卡占用”登记 A 和时间，结束后恢复空闲；核对没有其他 Notebook 或服务控制音频。现场人员确认供电与接线，值守且能立即切断音响电源。集中十几分钟操作不等于无人值守授权；网页输入和未验证的检测器不能成为唯一急停。

按冻结流程完成必要正向对照和有依据的工作点试验，正常就继续预定项目，最后一次反馈；不让人每做一小步就回聊天等待。低音量是启动条件，已通过的低增益基础阶段不重复。不能为听清而盲目加音量，也不能一直留在两种模式没有差别的低音量区。

同一对照固定硬件位置、麦克风增益、Codec 音量、实际 PL 增益编码、源及电平、时长和判据，按计划只改变 bypass。换夹具或条件时记录新身份并评估模型是否仍适用。停止项、失败项和未知项全部保留。

## 6. 实物验收和结果交付

本线必须回答：

- 外部讲话能否经麦克风进入系统并由音响清楚扩声。数字注入人声验证反馈环路，不自动证明话筒扩声可用。
- 同一配置与增益下，抵消与旁路是否有可比较的实际差别。听感、数字匹配、声学增长和保护事件分别记录。
- 找不到阈值就写已测范围；早停、缺帧或有效观测不足时交未知/无效结果，不生成虚假 MSG/ASG。
- 静音、降增益、限幅和保护单列，不能算同增益下的抵消成功；保护中止也不自动等于声学失稳。
- 电学延迟和音质使用相应测量，不能拿 PL 仿真周期推算冒充端到端实测。

一次无声不能证明待机或位流坏，电平高也不能单独证明失稳。按冻结包保存区分解释的证据，不用临时改变判据把结果改成预期。

整批结束后把完整结果包一次交 C。C 负责复算、配对汇总并整合给 B；你不再承担所有统计与算法解释。原始 PCM 默认按授权留在板卡，统计和原始音频的传输权限分别核对。
