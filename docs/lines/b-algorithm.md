## 2. 目标、职责与边界

算法工作的目标：**在同一夹具、硬件设置和数字增益下，当前模型为何有效或无效，一个有依据的候选能否改善稳定性并保留正常人声。**

- 负责 `src/feedback/`、算法分析脚本、对应测试及算法证据；算法核如需改动，按分工说明保留基线并说明兼容影响。
- 不修改 A 的底层驱动、硬件观测接口和现场配置，也不修改 C 的批次、测量与保护判据。
- B 不加载 overlay、不改板卡寄存器、不远程发声。板卡本地静默计算由 A 协调执行。
- 接口语义变化先说明生产方、消费方和兼容影响，按仓库规则协调，不能让 A/C 临时猜怎么加载。

默认复用已有算法和授权数据，先完成**一个基线与一个有依据的候选**的比较。没有改善可以交付否定结果，不为追求改动数量展开多套架构或自适应路线。

## 3. 数据缺失时怎么推进

先核查获准使用的数据、模型和源码是否真的可读。数据至少确认夹具、声源、Codec 设置、采样率、单位、帧对齐、掉帧、捕获范围和来源；模型确认实际部署的量化系数及兼容版本。原始音频能否复制或分析以用户授权为准，“不含人声”不自动等于获准传输。

缺材料时，**一次列出最小清单**，分清已有、必须补、可选三类。向 A 请求已有记录或板卡本地静默计算，不默认要求重新采集。交静默脚本时同时给出输入文件、准确运行命令、预期输出、失败提示及不加载配置/不播放的说明。

不具备真实数据时，继续修正分析语义和准备可控用例；不得将合成结果称为真实模型收益。真实数据可用后，优先完成能改变候选选择的分析，不停留在“等 A”。

## 4. 长期遵守的算法评价规则

### 4.1 时域与频域使用同一因果约定

读取模型 `lag_first`，核对参考预测、RTL 历史索引和频域脚本。对于 `lag_first=1`：

```text
p[n] = Σ h[k] · u[n−1−k]
Ĥ(f) = exp(−j·2πf/fs) · FFT(h)
```

时域卷积、频域模型与 RTL 必须包含同一因果延迟。以实际模型字段和现行契约为准；临时分析脚本也须遵守，不因实现方式不同而省略相位。

使用相同输入交叉检查时域与频域定义。发现分析错误时，按修正后的定义重算受影响结论，再建议改硬件或加滤波。不要把分析脚本遗漏延迟误诊为 RTL 需要改变历史语义。

### 4.2 评价真正部署的 Q20 系数

以实际部署的整数系数解码后评价，明确舍入、累加、饱和和输出调度。浮点模型可辅助诊断，但候选收益必须用最终量化产物重算；同时存在浮点与整数系数时核对一致性。

基线与候选用相同数据、评价帧、频带和相干性规则。抽头数不同导致预热不同，应取共同有效区间，不能让窗口差异冒充收益。

### 4.3 指标与预测的边界

- 宽带预测误差、逐频点抵消深度 CD、有效残差路径的绝对幅度和实物 ASG 分开报告。
- `CD(f)=20log10(|H|/|H−Ĥ|)` 是比值；最差 CD 不等于最早起振频点，还要看有效路径绝对幅度与环路相位。
- 小增益条件是线性模型的充分稳定界，不是精确失稳阈值；有限频率栅格、相干门控和频带会漏掉未观测部分。不能把门控通过的频点当成全带保证。
- 相位估算与闭环模拟写清调度、激励、时长、线性和饱和假设。合成真值上的一致，不证明真实功放在不同电平下仍线性。
- **保护触发、预测饱和、削顶和静音不直接等于声学失稳，也不是 ASG 改善。** 模拟和实测应区分这些事件。
- 闭环残差/麦克风功率比包含外部声源与噪声，不能直接与开环路径 CD 当成同一指标比较。先核对参考点、相位、激励和估计方法。

### 4.4 训练与验证独立

核对各段编号、参考序列、延迟和电平。拼接不连续采集段时，排除边界造成的伪历史，说明处理方法。

拟合数据不作独立验收；用于选抽头、正则化或频带的数据标为开发集。反复调参后不能继续声称同一结果是独立验证。数据不足时报告开发比较，再给一次最小独立验证需求。

## 5. 算法任务的完整工作流程

1. **固定比较对象。** 写清基线、候选改变什么，以及什么结果会保留或否定候选。复用已有数据和已确认代码，不重新做基础音频验收。
2. **复核瓶颈。** 在正确 lag 与部署 Q20 下，找有效残差路径最大的频带，同时报告相干性、估计误差及未覆盖部分。
3. **实现一个候选。** 根据瓶颈选择最小有依据的算法或参数改进，保留基线。
4. **完成同条件比较。** 给量化后的时域、频域及必要闭环模拟结果，保留恶化频段和失败用例；饱和与失稳分开记。
5. **试验前预测。** 给预计变化方向、值得测试的范围、主导频带、假设与不确定性，说明什么观测支持候选、什么否定、什么只是观测不足。
6. **交 C 集成。** 提供完整兼容模型包和转发消息。A 负责底层与现场，C 负责测量与批次编排；实测回来先核对原预测，再修正模型，不只事后解释。

建议增益只是待测范围，不保证某一档“旁路一定叫、抵消一定静”。与 C 的停止机制、输出限制和观测覆盖不兼容时交 C 协调；B 不自行调松保护或操作板卡。

## 6. 交给 C 的完整模型包

优先沿用已有格式与目录，至少交清：

| 内容 | 必须明确什么 |
|---|---|
| 身份 | 基线与候选名称、版本、模型文件名和 SHA256、源码提交 |
| 场景 | `fixture_id`、Codec 音量、影响路径的模拟设置、采样率、声源和有效电平范围 |
| 系数语义 | 抽头数、`lag_first`、Q 格式、实际整数系数、偏置处理、舍入和饱和 |
| 兼容性 | 支持的 bitstream/接口版本及容量、是否补零、加载与拒绝条件；未确认项标明 |
| 数据依据 | 数据身份/哈希、授权范围、训练/开发/独立验证划分、窗口与相干性规则 |
| 比较结果 | 同口径基线/候选结果、改善与恶化频带、已执行和未执行的验证 |
| 事前预测 | 待测判断、范围与频带、线性/电平/相位假设、不确定性和否定条件 |
| 使用方法 | 完整文件清单、可访问的传输方式、准确路径、运行方法与恢复基线的方法 |

不要只给目录名或一张表。各电脑路径不相通；本地生成不等于 C 已收到，也不等于板卡已有。列清需转发的文件与说明，收到 C 的明确接收/兼容反馈后，才认为交接完成。候选包必须保留基线，以便公平对照。
