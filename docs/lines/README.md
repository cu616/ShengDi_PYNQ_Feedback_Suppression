# 三人并行分工与交付说明

2026-10-23，按队长确认的新分工更新。A 负责现场、板卡底层与硬件集成；B 负责算法、模型和事前预测；C 负责测量工具、数据质检、指标复算与实验包集成。三条线的通知由人转发，不能假定 AI 之间自动通信、目录共享或代码已经同步。

本文件是职责和文件边界的统一入口；动态进度及数字口径只在 [STATE](../STATE.md)，人工转发方法见 [WORKFLOW 第 8 节](../WORKFLOW.md#8-人工转发与批次交接)。共同要求见 [推进提醒](../rules/progress-mandate.md)。

## 1. 每条线承担一个完整交付

| 角色 | 独立回答的问题 | 可立即使用的输入 | 交付对象与成果 |
|---|---|---|---|
| A：实物、板卡底层与硬件集成 | 选定版本是否能正常扩声，现场对照表现如何？ | 已有可用板端实现、设备、C 已交付的可用实验包 | 给 C 一份含配置、原始结果位置、听感和异常的结果包；给集成所需的板端实现 |
| B：算法、模型与预测 | 模型哪里有误差，候选改变什么，预计实测会出现什么？ | 已授权的历史捕获、实际部署系数、算法与参考代码 | 给 C 一个兼容模型包、同条件比较、事前预测及否定条件 |
| C：测量、复算与实验包集成 | 数据能否回答问题，怎样让 A 一次完成实验？ | 历史正常/失败记录、可控测试信号、现有测评代码和 B 的可用模型 | 给 A 一份固定版本的可执行实验包；给 B 有效数据清单及复算结果 |

三条线都负责自己的分析、实现、验证与交付。B 不是仅解释 A 的结果，C 不是仅做报表，A 不再兜底拼装所有脚本。各线的人类负责人负责确认本线成果能被使用，不把转发 AI 回复当作完成交付。

每轮任务只用一个问题、配置前提、完成标志、失败出口组织；统一执行规则与现场必要条件见
[WORKFLOW 第 2 节](../WORKFLOW.md#2-ai-会话的标准动作)。三线无需对所有动作会签；只在前提改变或结论将改变路线时汇合。

## 2. 怎样并行，什么时候必须等待

1. B 用已有数据分析并比较模型；C 用已有失败数据和可控信号验证测量工具；A 推进真实话筒扩声使用流程、必要板端实现和现场准备。三条线均不把新采集作为全部工作的起点。
2. C 在一个约定的集成点，将 A 的板端版本、B 的可用模型和测量程序组成实验包。有可用基线时直接沿用，不为等待新候选停掉所有工作。
3. A 执行批次 N 时，B 分析已有数据及候选，C 复核历史结果或准备后续工具。普通新建议进入下一批，不中途改变运行版本。
4. A 结束后一次交回结果包；C 检查有效性、汇总并向 B 整理数据说明，B 对照事前预测分析偏差。需要新实测的决定在下一个集成点汇合。

预先列出继续/跳过/停止分支，可减少现场聊天，但不能取消真实依赖。参考错位、无有效捕获、版本不兼容等会影响后续判断时，停止依赖它的项目。紧急停声和明确会使整批无效的问题立即转发，不等收工；其他问题合并为一次交接。

## 3. A：把现场工作集中完成

- 固定一个可复现的正常扩声场景，确认物理接线、声源、位置及实际版本。需要正常人声从麦克风进入并经系统扩声的证据；数字文件直接注入扬声器不能替代这一使用流程。
- 维护板卡驱动、Codec/I²S、寄存器访问、观测 RTL、缓存和硬件构建。C 给出的底层修正需求或补丁由 A 集成；涉及 B 的算法核语义先协调。
- 现场只使用已准备好的完整包。先完成脚本、配置和静音初始化，再提示人开始声源或操作。每批一次确认约定条件，条件未变不逐档重复询问。
- 近啸叫边界的有声测试仍需现场值守、可及时停声；批次自动运行不等于无人值守授权。失败时保留数据，停止条件触发后不自行继续升档。
- 一次交回配置、运行身份、版本/哈希、成功与失败记录、实际听感和结束状态。A 负责现场事实，不为填表猜测模型失效原因。

给用户的每一步写清：目的、操作位置、具体动作、是否发声及预计时长、预期输出、失败后动作、需返回的结果。文件位置区分电脑绝对路径、板卡绝对路径和浏览器地址；Notebook 使用“第几代码格＋标题/首行”定位，不能只说 `In[3]` 或“运行下一格”。上传步骤要有源文件、目标目录、完整文件清单与同名文件处理方式；不要让人自己寻找或拼代码。

## 4. B：交模型，也交可以被否定的预测

- 先核对模型的参考点、因果延迟、量化系数和数据窗口，修正会改变候选判断的分析错误。针对同一数据与同一评价条件，比较基线和一个有依据的候选。
- 负责算法实现与验证，保留恶化频段和失败结果。训练、开发与独立验证分清；未取得数据时一次列出最小材料清单，同时推进不依赖该材料的工作。
- 实验前交代预期变化方向、值得测试的范围、主要频段、假设、不确定性，以及什么观测支持或否定候选。频域界、模拟估计与实测阈值分别标注。
- 向 C 交付可加载模型、兼容版本、数据依据及运行方法。维持现有格式时直接集成；接口语义变化按 WORKFLOW 协调，不临时要求 A 手改格式。
- 实测回来先检查原预测，再修模型。没有可靠收益可交否定结果，不以事后解释或增加算法数量充数。

## 5. C：交完整实验包，承担测量与软件集成

- 优先复用现有工具，先完成一套能处理当前失败案例的测量流程，不建设通用平台。原始捕获保持不变；纠正计算和分类时保存新输出，注明脚本版本及与旧结论的区别。
- 检查真实帧范围、源结束时刻、提前中止、掉帧与观测覆盖。末尾窗口仅支持该窗口的结论，提前中止的数据不能自动当尾段。
- 区分“数据无效”“证据不足”“保护中止”“观察窗内未见失稳”“有失稳证据”。必要时同时记录保护事件和有效性；稳定音调、削顶或预测饱和不能直接等同啸叫。不编造置信概率。
- 用历史案例和独立构造的信号验证时间窗口、分类、异常保存与批次停止分支。验证测量结论与验证停声能力分别说明。
- 复核 B/A 准备引用的关键数字，优先解决会影响下一次现场决策的矛盾。C 对测量有效性负责，B 对算法解释负责；双方不一致时列出证据与待决问题，不由某个角色口头“拍板”替代证据。
- 把板端版本、模型、计划、操作单和汇总组成一份 A 能直接运行的包。C 不登录控制板卡、不自行部署播放，底层修改交 A。工具故障由 C 修复，不能让 A 或用户临时补齐。

## 6. 文件所有权（按功能划分，不按整目录包揽）

| 所有者 | 主要维护范围 | 跨线修改方式 |
|---|---|---|
| A | `src/rtl/audio_pl_*.v`、I²S/Codec 集成、`build/` 对应构建、底层 `board/audio_*/...trial.py` 中的寄存器/采集/恢复、硬件与现场配置 | C 提具体需求或补丁，A 集成验证；不得改变 B 的算法核语义 |
| B | `src/feedback/`、`src/rtl/feedback_fir.v`、拟合/模型比较/路径分析脚本与对应算法用例 | 改模型接口、定点或调度语义前说明兼容影响，交 A/C 协调 |
| C | 批次/计划/会话协调、测评与汇总、操作 Notebook、实验包打包；例如 `closed_batch.py`、`sweep_plan.py`、`sweep_session.py` 和测评用例 | 遇到硬件寄存器访问或采集底层改动交 A；算法预测语义交 B |

混合职责文件先划定修改函数/代码段，不能仅凭它在 `board/` 下就由一条线全部接管。Notebook 中的现场配置由 A 确认，执行交互与说明由 C 集成；两人不同时改同一文件。算法核与数据接口版本本次没有变化。

各线使用独立工作目录和分支 `A`、`B`、`C`，`main` 由队长合并。任务未说明角色且不能从明确范围确定时问用户；只有 A 可以操板。提交授权和冲突处理统一按 [WORKFLOW 第 9 节](../WORKFLOW.md#9-提交与拉取让人只按回车)，不另建相反规定。

## 7. 两份交付包与人工转发

这里是交付内容清单，沿用既有目录与格式，不要求新建另一套协议或任务表。

| 交接 | 应包含 |
|---|---|
| B → C 模型材料 | 实际文件、版本/哈希、量化与 lag 语义、兼容 bit/接口、夹具与模拟设置、同条件比较、事前预测及否定条件 |
| C → A 实验包 | 完整文件和可取得位置、版本清单、唯一执行入口、物理准备、批次计划、继续/停止条件、操作单、保存位置、恢复步骤；软件已验证与待上板项分开 |
| A → C 结果包 | 实际配置、run/fixture 身份、模型/bit/软件版本、全部成功/失败记录、原始数据所在位置及授权范围、听感、停声与结束状态 |
| C → B 复核材料 | 可用/无效/不足记录及理由、复算结果和口径、与预测的具体差异、需 B 回答的一个决策问题 |

所有箭头均代表**AI 写好消息、由人原样转发**，不代表自动联网或共享盘。AI 必须标明收件人、文件、版本、准确位置、所需动作及完成标志；无法共享文件时明确附件清单。收到方核对能否打开及版本是否相容，一次回复缺失项或接收结果，不要求每个文件单独确认。

A 的结果先给 C 形成完整数据说明，需要 B 同时分析时由 C 写好可转发材料；紧急现场问题可直接找对应负责人。C 缺席时 A 可将同一个自包含结果包分别转 B/C，保留“待质检”标记，不让集成责任变成所有工作的单点阻塞。

不再维护 `REQUESTS.md` 或其他 open/done 表。跨线请求在聊天中转发，仓库保留各线自己的进展、阻塞和交付证据。具体可复制格式见 [人工转发](../WORKFLOW.md#8-人工转发与批次交接)。

## 9. 分别给三个 AI 的提示词

先按 [跨设备交付入口](../ref/development-plan.md#跨设备获取本轮材料) 从 GitHub A 分支或交付提交取得文件。将对应文件全文复制给该线 AI，附本轮任务、仓库地址和提交号；不再转发队长电脑的绝对路径作为唯一取得方式：

- [A：现场、底层驱动与硬件集成](a-field.md)
- [B：算法、模型与事前预测](b-algorithm.md)
- [C：测量、复算与实验包集成](c-measurement.md)

人只需转发 AI 已写完整的交付消息，不需自行总结技术结论。是否完成交接，以对方能取得文件、理解版本并执行约定动作判断；本地生成、提交 Git 或写了一个路径，都不能自动代表对方已经收到。
