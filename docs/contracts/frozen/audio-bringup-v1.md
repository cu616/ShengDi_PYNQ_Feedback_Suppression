# Audio bring-up v1（2026-10-14）
>
> **已冻结（2026-10-20）。** 本文描述的 overlay 是诊断或中间版本，已被 `audio-closed-v1` 取代；
> 保留作历史依据，**不要按本文新增实现、也不要据此加载板卡**。
> 现行契约见 [../README.md](../README.md)。


状态：已做静音上板检查；未做有声直通或 ADC 数据验证。负责人：AI 实现，团队现场验收。目标：最小 PL 连续采样、可衰减、可静音和限时停止；不是 AFC。

- 输入输出：24 位二补码左右声道，I2S 使用官方 PYNQ v2.4 iis_ser/deser。
- PL 时钟 100 MHz；BCLK=100 MHz/32，LRCLK=100 MHz/2048，即 48828.125 Hz（设计值，待上板确认）。不可把 48000 Hz WAV 头作为实际时钟证据。
- 所有处理同属 clk 域；输入数据两级同步，内部 BCLK/LRCLK 为使能时序参考而非新逻辑时钟。
- 控制字：bit0 enable；bits3:1 算术右移量 0..7（只衰减，无放大）；其他位保留为 0。enable 上升沿启动一次最多 MAX_FRAMES 帧；保持高电平不会自动重启。先写 0 再写 enable 重启。
- 默认 MAX_FRAMES=244141，约 5 秒；按接收有效帧计数，不是独立墙钟看门狗。无接收帧超过 4096 个 clk 周期会停止输出；复位、enable=0 均静音。输出门控可能截断一帧，不宣称无爆音。
- 计数：frame_count 累计收到的完整帧，reset 清零；active 表示已启动且未到限额。没有 DMA、同步日志或溢出检测功能，不能以 frame_count 证明无丢样。
- 增益：24 位 signed 算术右移，负数向负无穷取整；没有放大故无增益溢出，不伪称实现了限幅器。
- 输出取上一个接收完整帧的结果；精确 I2S 延迟由仿真和实测确认，不将 PL 核延迟视为 ADC-DAC 延迟。
- 旧 base.audio API 不能直接驱动这个新核心。板上实际 R1 PLL 寄存器 `0271023c2103` 对应 49.152 MHz/48 kHz，与此 PL 的 48,828.125 Hz 不同；静音测试已确认 10 MHz MCLK、整数 R=5 的 50 MHz PLL 可锁定，并在结束后恢复原寄存器。该临时设置不自动随 bitstream 生效，有声测试程序必须明确配置、核对并恢复。证据见 `report/verification/audio_bringup/`。
- 外部 I/O 诊断仅为初步模型：Codec Rev. F Table 7 给出 ADC_SDATA 最迟 50 ns、DAC_SDATA 与 LRCLK 对 BCLK 上升沿各 5 ns 建立/保持。Vivado 临时时序检查仍有输入同步器首级 setup 与 LRCLK 输出 hold 违反项；这些路径需结合采样相位和 PCB 偏斜建模，不能把内部 WNS 当板级签核。

验证：人工可算的正负数、零、极值和所有移位；控制超时、重启、静音；I2S 收发集成另行测试。开启/关闭抵消及实际声学性能不在本阶段范围。
