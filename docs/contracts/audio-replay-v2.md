# audio-replay v2（运行时长上限放宽）

> 版本：v2　生效条件：队长 2026-10-25 批准　替代关系：v1 保留，仅运行上限不同
> v1 见 [audio-replay-v1](audio-replay-v1.md)；寄存器、系数、调度、保护语义**全部未变**。

## 唯一变更

| 项 | v1 | v2 |
|---|---|---|
| RTL 参数 `MAX_RUN_FRAMES` | 488281（10.0001 s） | **3000000（61.440 s）** |
| 驱动允许的单次时长 | 0.02 … 10 s | 0.02 … 61.44 s |

未改：寄存器地址与位段、32 位数据宽度、系数格式（Q20/24 位）、`lag_first=1`、
2 帧输出延迟、预测/残差/增益/混音饱和计数、保护与故障语义、ABI 版本号（`0x52`）。

## 兼容性

- 旧驱动 + 新位流：兼容（旧驱动只传 ≤488281）。
- 新驱动 + 旧位流：超限请求被 PL 拒绝，`capture_status` bit17 置位；**驱动必须报配置错误并停止，
  不得报成正常完成**。`live_run.py` 从同名 HWH 读取 `MAX_RUN_FRAMES` 判定所配位流能力，
  并在证据里写 `pl_max_run_frames` 与 `pl_contract`。
- 模型/标定/判据：不受影响。

## 观测范围（本次连续运行验收使用）

全程只有**寄存器时间线**（`completed_count`、`capture_status`、四类饱和计数，默认 20 ms 目标轮询）
加**尾部 PCM**（最后 16384 帧 = 0.336 s）。
**该证据只用于运行、保护与停止验收，不构成 60 秒全程音质或抗啸叫的证明**；
声学效果由 C 按有效观测范围另行评价。

## 风险与缓解

| 风险 | 缓解 |
|---|---|
| 单次暴露 10 s → 61 s | 保留全部保护：任一饱和计数非零即 disarm+mute；看门狗超时；停止文件/Ctrl-C |
| 长运行中状态漂移不可见 | 时间线记录帧数/状态/四类计数，并记录实际停止延迟与最大轮询间隔 |
| 上界被误当"可随意开高增益" | 只放宽时长；`control[31:16] <= 32768`（≤ +18 dB）未变 |

## 回退

改回 `488281` 重建位流，或直接部署 `board/audio_replay/rollback-v1/` 内的匹配包（见其 manifest）。
