## 路线选择

首版只验证桌面单通道扩声。助听保留为应用背景，不能用小盒子数据声称完成助听器验证。先争取固定几何位置下提高最大稳定增益；路径移动后的在线适应作为第二阶段。

最小信号链：麦克风/前置放大 → ADAU1761 ADC → PL接收 → 反馈估计相减 → 可调增益与限幅/静音 → PL发送 → ADAU1761 DAC → 有源音箱或功放 → 扬声器。输出的实际数字样本（包含数字增益、限幅与探测信号）分支进入参考历史缓存。功放与Codec模拟增益固定并记录。

PS负责Codec配置、参数、标定计算、系数装载和记录；PL负责逐样本实时链路。记录支路可以经DMA进入DDR，但不能让日志堵住音频主链。日志拥塞时丢日志并计数，音频继续运行。先单声道，Codec的双声道帧格式仍须正确处理。

设麦克风输入 m[n]=s[n]+(h*u)[n]，反馈估计为 (h_hat*u)[n]，相减结果 e[n]=m[n]-(h_hat*u)[n]。u是实际送往DAC的数字信号，h应包含DAC、功放、扬声器、空气、麦克风和ADC路径。实现使用已发生的输出历史并处理延迟对齐，不能构造当前样本之间的代数循环。

执行顺序：

1. 官方base overlay完成独立录音、播放的硬件检查。
2. 实现可插入处理模块的PL持续直通，加入静音、饱和与丢样计数；验证声音确实经过自定义PL。
3. 断开“麦克风实时送扬声器”的前向通路，用已知低电平宽带激励送扬声器，同时同步记录DAC参考与ADC输入。Python用NLMS或正则化最小二乘估计路径。保存原始数据与延迟，另用未参与拟合的激励验证。
4. 在Python先检查固定模型下的闭环，再把固定FIR系数装入PL，关闭在线更新，验证固定位置的反馈抵消。这一步已经能够检验“提前建模、抑制反馈”的主张。
5. 固定方案有效后才做路径变化检测、暂降增益、重新标定与平滑恢复。允许标定期间短暂中断扩声，并如实描述。连续在线NLMS/PEM或探测辅助更新均属于后续研究，不能靠简单叠加噪声就宣称解决有偏估计。

可加入少量窄带陷波作为对照或兜底，需单独测音色损伤。降增益/静音保护防止失控；保护触发时不计为“同等有效增益下成功抑制”。

先固定48 kHz作为候选采样率，按实际Codec配置验证。保留24位采样信息，算法字长由定点模型确定。FIR长度从128/256/512候选比较，以实际路径延迟与尾部能量决定；48 kHz下分别覆盖约2.67/5.33/10.67 ms，不能仅按麦克风距离决定。

48 kHz每样本约20.83 μs；100 MHz下约2083个时钟周期。256抽头FIR约12.288 M乘加/秒，适合先评估少量DSP时分复用。NLMS还需能量、除法、更新和访存，须分别预算，不能拿FIR吞吐率当整个算法的吞吐率。接口用RTL/现成已验证IP，FIR选团队熟悉的RTL或HLS；不预设HLS一定更慢、更费资源。

## 原备赛材料修正

| 原说法或安排 | 本项目处理 |
|---|---|
| 延迟每降低一点，就能多开一点音量 | 稳定性由整个环路频率响应决定；延迟改变相位与不稳定频率，MSG不保证单调。延迟实验可以做，不能预设下降曲线。 |
| 一米空气路径往返约6ms | 本系统扬声器到麦克风是一段声传播，1m约2.9ms；另一段是电子链路。 |
| 声音必须每次1μs，CPU不能做到 | 区分PL核延迟、ADC到DAC延迟和声学路径延迟。CPU/DSP也能实时处理，FPGA价值需用确定性、资源和接口实测体现。 |
| AD→PL→DDR→DA作为正式低延迟主路 | 首选PL持续流式主路；DDR用于观测。现成base驱动用于检查，不等于已提供所需的可插入AXI-Stream链路。 |
| 普通NLMS＋少量噪声必然正确抵消 | 闭环信号相关会导致有偏估计；优先开环标定、固定系数验证。噪声可能可闻，强度与标定时间要测。 |
| 128抽头够小盒子，512够开放空间 | 包含转换器延迟与混响尾部，按实测选择；不足就增长度或缩小验证场景。 |
| 16位数据×24位系数，用32位累加 | 全精度乘积需40位，256项保守累加需再加8位。若缩位须明确舍入、缩放、饱和及动态范围依据；实际24位输入更需重新计算。 |
| GAIN用Q1.15 | 必须明确符号和整数位定义；常见有符号Q1.15不能表达大于等于1的正增益。按目标范围设计。 |
| 256点FFT足以精准判断啸叫 | 48kHz下频点间隔187.5Hz，多帧还增加检测时间；峰值不能可靠区分乐音与啸叫。检测为旁路观察，先不放入主路。 |
| 冻结次数就是误切率 | 冻结自适应不等于衰减声音。分别记录误触发、有效语音增益变化和频响损伤。 |
| 小盒子等价助听器；孔越大反馈越弱 | 盒子只是测试夹具；孔径同时改变共振和频响，不保证单调。固定桌面几何也能复现。 |
| 首日必须拉出啸叫 | 首日先独立录放与静音；闭环测试应在连续链路验证后低音量进行。 |
| 32位不够就升40位/发散就缩滤波长度 | 先检查时序、参考对齐、极性、溢出、削顶和路径覆盖；缩短长度可能加重模型误差。 |
| Python黄金参考绝对正确 | 浮点模型也需已知路径测试；建立位精确模型，再与RTL逐样本精确比较。接近零时相对误差不合适。 |
| 有节目输入测THD+N | THD+N用规定频率和电平的正弦测试；语音/音乐另测频响、失真和听感。ASG不是唯一质量指标。 |
| Jupyter必须9090；找不到器件就申请Enterprise | 端口以镜像说明和实际服务为准；先检查器件组件、board files和器件型号。不要据此直接重装或买授权。 |
| alsamixer必能控制base.audio | 需确认实际驱动路径，PYNQ自有驱动不一定走ALSA。Z2的API也不能照搬Z1。 |

## 指标口径

首个成功判据是在有效声音增益没有被偷偷降低的情况下，固定场景ASG为正且超过重复试验误差。可把+3dB定为首轮内部目标、+6dB定为挑战目标；达不到时按实测报告，不改数据口径。

- 基线与处理模式共用同一Codec配置、采样率、主通路延迟、麦克风/音箱位置和模拟音量。比较时只切换抵消功能。保护阈值相同并记录触发。
- MSG以最后通过稳定性判据的增益报告，同时给出首次失败增益形成区间。建议每档1dB、观察10秒、连续窄带增长且持续0.5秒作为初始失败候选，再用数据调整并冻结规则；这些是试验起点，不是通用标准。每次从低增益重新开始，记录输入素材、背景、饱和情况和运行时长。
- ASG=MSG_on(dB)-MSG_off(dB)，或20log10(G_on/G_off)。记录实际小信号前向增益；发生限幅、保护降增益或静音的运行不计为成功。可以单列保护成功率。
- 电学端到端延迟：独立信号源→Line-in，示波器同一时基观察输入节点和板卡输出节点；不把实时输出直接接回其输入形成电正反馈。无示波器时用同步双通道采集并校准自身延迟。PL核延迟另用周期计数/ILA测，不能替代ADC到DAC延迟。
- 声学测量另含传播和换能器响应，不与电学延迟混报。分位数应基于足够次数，不从几个波形计算假精确P99。
- 音质：先固定电平正弦与扫频测削顶、频响，再用语音、音乐及持续音检查误伤，保留原始WAV。纯录音回放只能检查检测器，不能证明闭环稳定。
- 资源：LUT/FF/BRAM/DSP、实际约束频率、实现后时序报告；WNS非负之外还需检查未约束路径与时钟域。
- 可靠性：10分钟起步，再做至少30分钟运行；记录丢样、溢出、保护次数及重标定中断时长。

## 今天的操作

结合团队基础，首版不安排全手写NLMS、FFT或PEM。接口与FIR先用熟悉的RTL；Python只先学数组、WAV读取、绘图和FIR验证所需内容。已有SDK经验可用于后续Codec配置排查，但第一天走PYNQ官方示例。

Vivado 2018先保留，不卸载。PYNQ启动与现成base.bit录放不依赖电脑Vivado版本。记录2018的小版本；选定音频参考工程后核对其构建版本，在独立目录验证能否构建、加载、运行。能复现的旧版本可按指南在报告中说明；需要新版时再并行安装并固定工程版本，不在唯一工程副本上直接升级IP。若选择HLS还需另核对其工具流程。

1. 记录麦克风型号、供电、模拟/数字输出、是否有前置放大；记录音箱是否有功放、输入接口、电源。仅DO声控模块不能作为音频输入；I2S/USB麦克风也不能直接插模拟Line-in。模拟模块的直流偏置、幅度和耦合方式需查规格后确定。裸扬声器须经功放。
2. 查SD卡是否已有可用PYNQ系统，能启动就先保留。断电核对BOOT=SD、供电跳线匹配供电来源，参考手册连接PROG-UART和网络。优先同一路由器DHCP；地址与网页端口按镜像实际配置。
3. 在板上Jupyter运行下面只检查环境的代码。加载base前确认没有正在运行的自定义任务；它会重新配置PL。

```python
import pynq
from pynq.overlays.base import BaseOverlay
print('pynq:', pynq.__version__)
base = BaseOverlay('base.bit')
print('audio available:', hasattr(base, 'audio'))
audio = base.audio
print(type(audio))
print([name for name in dir(audio) if not name.startswith('_')])
```

4. 对已确认兼容的模拟麦克风，用板上base/audio官方示例先录5秒再播放。下面对应官方AudioADAU1761 API，实际镜像若无同名接口先检查其示例，不盲换驱动。

```python
# 仅在接口和供电确认后执行；录音时保持外部功放静音。
audio.set_volume(0)  # 官方API中是最低音量，不是保证静音
audio.select_microphone()  # 仅用于兼容Mic连接
# 若使用已核对电平的Line-in输入，改用 audio.select_line_in()
audio.record(5)
audio.save('mic_check.wav')
# 此时录音已停止。解除外部功放静音，从低音量试听；不要执行bypass。
audio.play()
```

5. 保存录音、版本输出、接线记录和回放是否正常。今天的验收是输入输出分别可用；这不算实时直通，更不算AFC。闭环测试等PL连续链路和硬件静音就绪后再做，低音量短时测试，不佩戴耳机拉啸叫。

需要团队补充：外设准确型号/接口、是否能打开Jupyter、Vivado版本、成员基础及报名后台截止日期。器材未确认前不提供猜测性的针脚接线，也不要求先采购第二只麦克风或制作密闭腔。
