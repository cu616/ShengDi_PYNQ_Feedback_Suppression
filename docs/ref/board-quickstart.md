# 板子怎么用（速查）

适用：`xc7z020 PYNQ-Z2` + `audio_replay_io` 位流。只讲现场用得上的东西。

## 一、四个按键（蓝色，板子边上）

| 按键 | 作用 | 怎么按 |
|---|---|---|
| **BTN0** | 开始重标定 | **按住 1.5 秒**再松（短按会被忽略） |
| **BTN1** | 开始 / 停止扩声 | 点一下 |
| **BTN2** | 确认环境安静 | 点一下 |
| **BTN3** | **急停**：立即静音并中止 | 点一下，任何阶段都生效 |

## 二、两个拨码（红色，SW0 / SW1）

| 拨码 | 作用 |
|---|---|
| **SW0** | **拨上去 = 旁路**（关掉抗啸叫，只听原声）；拨下来 = 抵消开 |
| SW1 | 保留，不参与现场 |

**SW0 的切换会立刻生效**，不需要重启，不需要重标定。

## 三、四个 LED（LD0–LD3）

| 灯 | 含义 |
|---|---|
| 全灭 | 空闲 / 静音 |
| 只有 LD0 亮 | 重标定进行中 |
| LD1 亮 | 请说话（提示音已放） |
| LD2 亮 | 请保持安静（测底噪） |
| LD3 亮 | 就绪 / 正在扩声 |
| 四个全亮 | 出错或保护停声 |

拨码旁路时 **LD3 会被强制点亮**，用来区分"旁路"和"抵消"——这是硬件行为，不依赖软件。

## 四、换一个距离，怎么做

**不需要复位板子。**按顺序：

1. 把音箱和麦克风摆到新距离（两者距离一起改）；
2. **长按 BTN0**（1.5 秒）→ 进入重标定；
3. 看灯：**LD2 亮**时保持安静；**LD1 亮 / 提示音**时开始正常说话；
4. 自动采集、拟合、判定；成功则 LD3 亮；
5. **点 BTN1** 开始扩声试听；
6. 要对比抵消效果：**拨 SW0** 上下切换；
7. 结束：**点 BTN3** 或 BTN1。

**每次换距离都要重新标定**——旧模型只对原几何有效，不要拿旧模型直接跑。

## 五、出问题怎么复位

| 情况 | 做法 |
|---|---|
| 程序卡住 / 没反应 | 按 **SRST** 按钮（PS 重启，约 30 秒恢复） |
| 完全没声音、灯也不动 | **断电**（拔电源 10 秒再插回） |
| 音频通路报 PLL 错误 | 跑 `bash recover_audio.sh`（重下位流）；再不行就断电 |

## 六、几个已知限制（别当成故障）

1. **每次采集前约 1 秒**在重下位流，这期间没声音是正常的；
2. 采集只保留**最后 0.34 秒**，所以说话要**说到最后**，不能提前停；
3. 单次扩声最长 **61.44 秒**，到点会自动停；
4. 说话**靠近麦克风会削顶**（硬件会直接停声保护，灯变四个全亮）——把讲距保持在 35 cm 左右。

## 七、一条铁律（2026-11-02 踩过）

**shengdi-product.service 在跑的时候，不要再从 SSH 跑任何碰硬件的脚本。**

服务独占 FPGA；另开一个 PYNQ 会话（下载 overlay、读写 /dev/mem）会和服务抢同一个设备，
实测会把 PS 卡死到 **LED 全灭 + SSH 不通**，只能断电恢复。

- 只想看状态：读 ~/.local/state/shengdi/status.json（纯文件，安全）；
- 要跑硬件脚本：先 sudo systemctl stop shengdi-product.service，跑完再 start；
- 现场标定**全程用物理按键**（CAL/START/STOP + SW0），不需要 SSH。

脚本里的判据见 oard/audio_replay/hw_guard.sh 的 hardware_allowed。
