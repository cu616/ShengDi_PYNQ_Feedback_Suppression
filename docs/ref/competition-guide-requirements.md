# 选题指南（AMD 赛道）与本仓库工程规范对照

来源：`references/competition/amd-fpga-guide-2026.pdf` 第 3.3 节（PDF 第 22–25 页，印刷页 19–22）。
本页只摘录与工程规范、交付结构、协作记录有关的原文要求，并注明本仓库的对应落点。
评分与截止时间以官方公布为准；本页不替代官方文件。

## 1. 赛道与考察重点（3.3.1–3.3.2，PDF p22）

- 面向完整 FPGA 作品，器件/实现方式/应用领域不限；分初级组、高级组，独立排名评奖。
- 评测重点：**功能是否正确、是否经过实测验证、性能与资源数据是否真实完整、他人能否复现**；
  在此基础上创新性与应用价值权重最高（3.3.2 考察重点）。
- 推荐 PYNQ：PS 侧 Python/Jupyter，PL 侧 HLS/RTL 封装 Overlay。
  **通用性较高的 PYNQ Skill 可加分**，指不与本队题目绑定、换题目/换板卡仍可用的技能。
- 技能包可以是：从接口契约生成主机调用代码的脚本、黄金参考对比/性能与资源数据自动采集工具。

## 3. 提交内容（3.3.5，PDF p24–25）

### 3.3.5.1 工程包

完整工程文件与源码（RTL/HLS/PS 软件按实际方式提交）；仿真或验证结果；
**综合与实现报告（资源占用、时钟频率、关键性能指标）**；上板工程、运行脚本、实测输出与参考结果对比；
可复现的构建脚本。

### 3.3.5.2 技能包（重点）

- **放在 `skill/` 目录，含 `README.md`**，说明**每一项**的适用范围、使用方法与失效条件。
- 技能包 = 与大模型协作过程中沉淀的经验**显式提炼**，供他人直接复用；可以是任意一种或多种：
  1. **提示词工作流**：经过验证、能稳定完成某类任务的提示词模板及使用说明；
  2. **案例模板**：下一个题目能直接套用的工程骨架、脚本模板、报告模板；
  3. **校验脚本**：自动比对黄金参考、检查资源与时序、验证工程可复现性的脚本；
  4. **踩坑清单**：结构化整理的常见错误与定位方法，含触发条件与排查步骤。
- **评价标准是可复用性**：一支陌生队伍拿到该目录，能否直接用在自己的题目上。
  **每一项须写明：适用场景、使用方法、已验证的效果，并说明是从哪些失败或观察中总结得出。**
- **通用 PYNQ Skill 单独加分**（面向 PYNQ 框架且不与本队题目绑定，换题目/换板卡仍可用，见 3.3.2）。

### 3.3.5.3 设计报告

选题背景与创新点（解决了什么实际问题、前人做过什么）、设计原理与功能框图、
软硬件划分依据与接口设计、优化过程含优化前后性能与资源对比表、
**大模型协作记录**（提示词、模型回答、自我纠错轨迹、智能体工作流设计）、
**技能包的提炼过程**（从哪些失败/观察总结、如何验证有效、边界如何确定）、
可从零开始完整执行的复现说明。

### 3.3.5.4 推荐目录结构（重点）

```
<project_name>/
├── README.md     # 项目简介 + 复现步骤
├── src/          # 设计源码（RTL / HLS / PS 侧软件）
├── sim/          # 仿真或验证脚本与结果
├── build/        # 可复现的构建脚本 + 综合与实现报告
├── board/        # 上板工程、运行脚本与实测输出
├── data/         # 测试数据与参考结果
├── skill/        # 技能包
│   └── README.md
└── report/       # 设计报告 + 大模型协作记录
```

- 推荐而非强制；采用其他组织方式的队伍**必须在 `README.md` 中给出目录对照说明**。
- **所有目录名与文件名必须使用纯英文（小写字母、数字、下划线或连字符），
  不得出现中文、空格或特殊字符**，中文只出现在文件的正文内容中。
- 本仓库对照表见根 `README.md` 的「目录对照（评测指南 3.3.5.4）」。

### 3.3.5.5 评测指标与权重

| 评测项 | 权重 |
|---|---|
| 创新性与应用价值 | 30 |
| 性能与资源优化效果 | 20 |
| 功能正确性与设计完整性 | 20 |
| 大模型协作与技能包 | 15 |
| 文档质量与可复现性 | 15 |

两组同一套指标与权重；组内独立排名评奖。功能正确性与可复现性以提交物核查与实测数据为主要依据。
