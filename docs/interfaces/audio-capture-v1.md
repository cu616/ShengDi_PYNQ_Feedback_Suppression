# Muted contiguous ADC capture v1 (2026-10-16)

Purpose: diagnose why official `base.bit` records intelligible LINE_IN speech but the current custom PL ADC→DAC trial only produces hiss. This is an **independent diagnostic overlay**, not a feedback suppressor. It reuses `audio_pl_probe` and adds a 4096-frame, 24-bit stereo memory capture. DAC control remains zero throughout the board script. No PCM file is saved by the script.

- Source/format: `audio_pl_probe` latches left/right ADAU1761 ADC samples on `rx_valid`. Two 24-bit two's-complement words are stored per frame, unshifted. The PL clock is 100 MHz, and generated LRCLK nominally 48,828.125 Hz. 4096 frames span about 83.9 ms. Because capture clocks are generated in PL, this is not an independent sample-rate measurement.
- Start/stop: `audio_capture_cmd` GPIO channel 1 bit 16 arms capture; writing 0 clears count/done. After arm, one frame is stored at each `frame_count` change until 4096. Done then latches high and the memory is stable until disarm. A stuck ADC frame prevents completion; board script times out after 2 s and restores official overlay. No automatic continuous rearm.
- Read: channel 1 bits 11:0 select a frame index. The synchronous dual-port RAM read has two registered stages; PS GPIO write/read latency exceeds those stages, but callers should not infer zero-cycle readback. `audio_samples` GPIO returns captured left and right 24-bit words. Do not read before done or while disarmed.
- Board HWH addresses for this exact build: `audio_control` `0x41200000` (channel 1 output control at +0, frame count input at +8); `audio_samples` `0x41210000` (left input +0, right input +8); `audio_capture_cmd` `0x41220000` (command output +0, status input +8). Status bit 0 is done, bits 13:1 are captured count (0..4096). All other status bits reserved. These addresses and widths are version-specific; rebuilds must reread matching HWH.
- Safety: board script mutes Codec output and sets control GPIO 0 before PLL/input configuration; it never enables PL DAC. `finally` clears capture/PL control, mutes Codec, reloads stock `base.bit`, restores stock PLL `0271023c2103`. The 4096-frame bound depends on receiving frames; the script has a 2 s wall-clock timeout for capture completion. Physical audio output should stay disconnected or headphones removed during first run.
- Board script `board/audio_capture/muted_frame_capture.py` returns only summary values (RMS/peak dBFS and strongest 100–5000 Hz bin for left channel), not raw PCM. A peak in quiet noise is not a validated acoustic tone; compare controlled quiet/tone conditions and the official base reference. Samples exist transiently in PL/PS memory and are not written to disk.

Validation: Vivado 2018.3 behavioral simulation passed a reduced 16-frame instance, checking completion, indexed readback and muted output. A separate dynamic I²S simulation of the underlying probe passed 24 changing left/right words, including positive/negative patterns and expected one-frame latency. Full 4096-frame RTL synthesized into 5 RAMB36E1 and 1 RAMB18E1 and implemented with DRC 0; timing report WNS 3.423 ns, WHS 0.034 ns under the **existing incomplete external audio I/O constraints**. On 2026-10-16 the matching files were uploaded to the PYNQ-Z2 and `capture_stats('ambient')` completed: 4096 frames; RMS left/right −32.53/−32.51 dBFS; `dac_muted=True`, `PL_CONTROL_MUTED True`, `STOCK_BASE_RESTORED`, stock PLL readback `0271023c2103`. The external sound condition was unverified, so this is not a quiet-noise baseline. The board result proves bounded contiguous readback, not ADC sample fidelity, intelligible speech or feedback suppression. Notebook: `base/audio/audio_capture/muted_capture_2026-10-16.ipynb` on board.
