# Muted TX diagnostic v1 (2026-10-15)

Purpose: separate an inaudible acoustic result from PL processing/serializer inactivity. This is a diagnostic variant of `audio_probe`, not an AFC algorithm or a replacement for the known probe bitstream. The source and build recipe are `src/rtl/audio_pl_diag.v`, `build/scripts/create_audio_diag.tcl`, and the Vivado 2018.3 test/synthesis/implementation scripts of the same suffix. Matching board files are `board/audio_diag/audio_diag.bit/.hwh`.

The existing `audio_control` register at `0x41200000` retains channel 1 control word (`+0x0`) and channel 2 frame count (`+0x8`). Bits `[3:1]` are the arithmetic right shift; bit 0 enables the bounded internal frame path. New bit 4 is **diagnostic physical output mute**: with bit 4 set, the external `sdata_o` pin is forced low while the internal frame path and serializer keep running. Bits outside these fields are not specified. The existing ADC snapshot GPIO remains at `0x41210000` (left `+0x0`, right `+0x8`, valid bits `[23:0]`).

A new AXI GPIO `audio_tx_status` is assigned by this version's HWH to `0x41220000`: channel 1 `+0x0` counts received frames whose internal left or right processed TX sample was nonzero; channel 2 `+0x8` counts BCLK falling edges on which the internal serializer data bit was one. Both are 32-bit wrapping counters, reset by PL reset and retained after control bit 0 goes low. They are diagnostic activity counts, not PCM data, sound level, a CRC, or proof that the physical DAC received valid data. A `tx_nonzero_frames` update checks the prior registered sample on the same `rx_valid` edge; its count can lag one frame. The serializer count likewise observes registered internal data around the BCLK edge; it only establishes activity.

`board/audio_diag/muted_tx_diag.py` loads the matching overlay, keeps the Codec output muted, sets control word `1 | (6 << 1) | (1 << 4) = 29` for one second, reads both counters, clears control, restores official `base.bit` and the stock Codec PLL in `finally`. No recording is saved, and no audio output is requested. The test does not need a person to speak or a phone to play. If either TX count is zero, the script raises after printing the observed values but still attempts restoration. This version has no independent wall-clock watchdog; the RTL path has its existing approximately five-second frame limit. The HWH and board script addresses must remain paired.

Vivado 2018.3 behavioral simulation passed `AUDIO_DIAG_PASS`, including counter growth specifically in bit-4 diagnostic mode and continuous external output mute under that mode. Synthesis and implementation completed; implementation DRC found 0 violations and reports WNS 3.456 ns, WHS 0.034 ns **under the current incomplete external I/O constraints**. Board execution in the independent Notebook returned 48,890 frames, 48,884 nonzero processed frames, and 1,181,037 internal serializer one-edge events over about one second, followed by PL mute, stock base restoration and original PLL readback. These are internal counters, not a pin measurement or audible test. This version does not resolve the audio I/O timing signoff question in `audio-bringup-v1.md`.
