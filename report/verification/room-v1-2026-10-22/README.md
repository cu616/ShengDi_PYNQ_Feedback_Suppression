# 2026-10-22 B 线：房间夹具的低频问题不是"估计器"，是 256 抽头的时长不够

> 数据：A 于 2026-10-22 交付 `candidate_room_v1_256_final`（9 段 × 16384 帧，
> 每段 reference / microphone / prediction_pcm / residual_pcm）。
> 夹具 `room_v1_20261021`：0.5 m、HP NS1 Pro、MAX4466、`hp_volume=40`、
> 0 dBFS 宽带噪声注入、箱盖无关（桌面摆放）。
> 本文数值为模型推算，不是实测 ASG。

复现：

```text
python scripts/analyze_room_taps.py --data-dir <含 seg_*.npz 的目录>
```

产出 `analysis.json` / `run.txt`（本目录）。

## 1. 先说数据：只有 4 段能一起用，不是 6 段

A 判定的"可用"依据是电平（`mic_rms_dbfs > -25`），据此 6 段可用。
但跨段拼接还要求**时序一致**，这一条没有检查：

| 段 | mic 电平 | ref→mic 延迟 | 判定 |
|---|---:|---:|---|
| seg_1 / seg_5 / seg_6 / seg_7 | −13.2…−15.1 dBFS | **+125** | 可用 |
| seg_0 | −14.8 dBFS | **+124** | **剔除**（差一帧） |
| seg_2 | −14.9 dBFS | **+124** | **剔除**（差一帧） |
| seg_3 / seg_4 / seg_8 | −37.5…−37.8 dBFS | 0 | 静音，本来就不可用 |

差一帧的证据不止互相关：seg_0 的 `prediction_pcm` 相对 mic 的相位差随频率线性增长
（300–1000 Hz −1.9°、1–3 k −15.5°、3–6 k −33.3°、6–12 k −69.7°），斜率对应 **1.05 帧**；
seg_1 / seg_5 的相位差在 −5…+10° 之间且不随频率增长。所以那两段的
`mic − pred` 只有 −0.3…−0.4 dB 的抑制（其余段是 −8.4…−9.7 dB），是数据问题不是算法问题。

**结论：房间夹具现在有 4 段可拼接，不是 6 段。** 下面的交叉验证用
`seg_1+seg_5` 拟合、`seg_6+seg_7` 评价（30720 帧 / 30720 帧，全样本外）。

## 2. 回答第 1 问：300–1000 Hz 的残差并不比 6–12 kHz 高

| 模型 | 300–1000 残差 | 6–12 k 残差 | 低频 − 高频 |
|---|---:|---:|---:|
| shipped 256（低 SNR 标定） | −1.11 dB | +3.46 dB | **−4.57**（低频更好） |
| refit 256（高 SNR） | −1.13 dB | −5.94 dB | +4.81 |
| refit 384 | −6.99 dB | −6.98 dB | −0.01（持平） |
| refit 512 | −9.45 dB | −6.12 dB | −3.33（低频更好） |
| refit 680 | −4.25 dB | −5.06 dB | +0.81（持平） |

**所以低频不是"特别难"的那一段。** 用 512 抽头时，低频的残差甚至比高频低 3.3 dB。

A 原来的判断依据是"300–1000 Hz 相干 0.32、模型峰值 −0.68 vs 实测 7.71"。
相干 0.32 是低 SNR 标定数据的问题，这批高 SNR 数据里 300–1000 Hz 的相干中位是 **0.74**，
残差也确实降下来了。**这一半的怀疑是对的：原标定的信噪比确实拖累了低频。**

但"信噪比"不是全部。见下一节。

## 3. 真正的问题：256 抽头在 300–3000 Hz 的最差频点上是负的

同一批数据、同一评价口径，只看 CD（最差频点的抵消深度）：

| 模型 | 300–1000 | 1000–3000 | 3000–6000 | 6000–12000 | 全带 ASG |
|---|---:|---:|---:|---:|---:|
| **shipped 256** | **−0.53** | **−1.96** | +3.26 | +0.20 | **+6.73 dB** |
| refit 256 | −0.62 | −2.80 | +2.86 | +2.33 | +11.32 dB |
| refit 384 | −0.13 | +2.08 | +4.82 | +1.86 | **+16.80 dB** |
| **refit 512** | **+5.41** | **+3.76** | +6.38 | +4.32 | **+16.32 dB** |
| refit 680 | +7.30 | +2.15 | +7.32 | +6.45 | +14.45 dB |

**shipped 256 在 300–3000 Hz 的 CD 是负的**——那不是"抵消得少"，是最差频点上
抵消后的环路比抵消前更强。高频反而为正（+3.26 / +0.20）。

这与"A 的实测：同一增益下抵消能把麦克风压低约 20 dB"并不矛盾：
**宽带 RMS 压低 20 dB，同时最差频点是负的**——这正是"平均好看、最差点没压住"的典型形态，
也正是 ASG 只有 4.0 dB 的原因。

## 4. 回答第 2 问：一个改法 —— 加抽头到 512

不给三个选项，只给一个：**把 256 加到 512。** 理由有三条，都能从表里读出来：

1. **512 让模型的低频峰值对上实测**：300–1000 Hz 的 `max|Ĥ|` 从 −1.03 dB
   提到 **+5.09 dB**，而实测是 **+4.70 dB**——差 0.39 dB。256 差了 5.7 dB。
2. **512 把负 CD 全部翻正**：−0.53 → +5.41（300–1000）、−1.96 → +3.76（1000–3000）。
3. **512 是全表里最均衡的**：384 的全带 ASG 更高（16.80 vs 16.32），但它的
   300–1000 CD 只有 −0.13，仍在临界线上；512 四个子带全为正。

### 4.1 为什么不是"加正则 / 预白化 / 重分配抽头"

- **加正则**：现在 `ridge=1e-6`，条件数 251。残差不是被正则压出来的——
  refit 256 用同样的 ridge 已经把宽带误差做低了，问题是**时长**，不是数值稳定性。
- **低通预白化**：它改变的是拟合权重，不改变 256 个抽头能覆盖的时间窗。
  覆盖不到的部分，权重怎么调都还是在覆盖不到。
- **重分配抽头（同样 256 个 MAC、抽头间隔加倍）**：这确实能把覆盖时长翻倍，
  但频率上限同时砍到 12 kHz。而这批数据里 **6–12 kHz 的 `|H|` 是 10.27 dB，是全带最强的**，
  砍掉它不划算。加抽头只用时间、不用硬件，比重分配更划算。

### 4.2 加抽头的代价：只是参数，不是架构

RTL 是单 MAC 时分复用，每抽头 3 拍 + 3 拍收尾：

```text
256 → 771 拍   384 → 1155 拍   512 → 1539 拍   680 → 2043 拍
帧预算 2048 拍 → 上限 681 抽头
```

512 用 1539 拍，还剩 509 拍余量。**所以"加抽头"不需要增加 MAC 单元，
只是把每帧的迭代次数改大，属于改参数。** 这一点是 A 说"不用改 RTL"的关键修正：
不是"值不值得改"，而是"改起来本来就很便宜"。

## 5. 对 A 那个判断的评估

A 说："差距主要来自低频模型精度，不是算法——同一增益下抵消能把麦克风压低约 20 dB，
说明抵消在工作，只是'能多推多少'被模型限制了。"

**方向同意，措辞要改两处：**

1. 不是"低频"精度，是"**300–3000 Hz 最差频点**"的精度。低频在高频之下并非更难；
   负 CD 覆盖的是 300–3000 Hz，而高频（3 k 以上）本来就是正的。
2. "能多推多少被模型限制"——对。限制它的具体量是 **CD 最差**（−0.53 dB），
   不是宽带误差（那个已经把麦克风压低 20 dB 了）。这两个数可以差十几 dB，
   这次又是同一个教训。

## 6. 还有一个数字要纠正：512 不是"多 1.3 dB"

A 用"256 做到 6.9 dB、512 做到 8.22 dB，只多 1.3 dB"判断"256 就够"。
那是**宽带预测误差降低**。换成 ASG 口径，同一批数据同一评价段：

| | 256 | 512 | 差 |
|---|---:|---:|---:|
| 宽带预测误差降低 | A 报 6.9 | A 报 8.22 | +1.3 dB |
| **全带 ASG（本文）** | **+11.32** | **+16.32** | **+5.0 dB** |
| **300–1000 的 CD** | **−0.62** | **+5.41** | **+6.0 dB** |

所以"只多 1.3 dB"这个判断，又一次用了一个对目标不敏感的量。
**决定"能多推多少"的是 ASG，而 512 在 ASG 上多 5 dB。**

## 7. 局限

- 只有 4 段可拼接（30720 帧训练 / 30720 帧评价），比箱体那批少；CD 的点估计有 ±1 dB 量级的抖动。
- 相干门控取 0.5 而非 0.8：300–1000 Hz 的相干中位只有 0.74，门控 0.8 会剩不下几个 bin。
  本文的全带 ASG 在门控 0.0…0.8 下完全不变（max 都取在高相干 bin 上），所以这一条不影响结论。
- 所有 ASG 都是线性小信号推算。A 实测的 4.0 dB 与本文对 shipped 256 的 +6.73 dB
  差 2.7 dB，来源未查清（可能是 H 的口径或门控），**但"512 比 256 好 5–10 dB"这个相对结论不依赖它**。
- 没有做 RTL 改动，也没有上板验证 512。1539 拍的结论来自既有接口文档的时序公式，不是本轮实测。
