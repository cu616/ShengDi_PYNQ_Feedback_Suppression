# 2026-10-23 A 的数据包复核：8.4 kHz 不是瓶颈，300–1000 Hz 是这批数据测不出来

输入：`manifest/`（6 段旁路直采，16384 帧/段，ref RMS −24.0 dBFS，mic RMS −25.1 dBFS，
延迟全 125，`gain_q12=0`）+ `model_256.json` / `model_512.json` / `model_256_pad.json`。
对照场次：`candidate_room_v1_256_final(1)/`（9 段，其中 seg_1/5/6/7 可用，mic −12.9…−14.8 dBFS）。

所有结论只用两种口径：**时域逐段残差**（与板上 `prediction` 逐样本一致）和
**显著耦合频点上的谱残差**。不用 `CD(f)` 的符号、不用 `max|H−Ĥ|` 的无门控最大值。

## 1. 摘要

| 问题 | 答案 |
|---|---|
| 两批数据一致吗 | 一致：`max\|H\|` 10.19（新，−25 dBFS）/ 9.87 dB（旧，−14 dBFS），差 0.3 dB |
| 我的重拟合与 A 的模型一致吗 | 一致：相关 0.9996（256）/ 0.9992（512），最大差 0.006 |
| refit 后 8.4 kHz 余量够吗 | 够：该带残差比带内 mic 低 **18.4 dB（256）/ 23.4 dB（512）** |
| 那 A 的「6–12 kHz CD 为负」是什么 | `\|H\|` 零点处的伪影，见 §6 |
| 300–1000 Hz 为什么只有 −2.3 dB | **这批数据在那里相干只有 0.49，测不出**；旧批 0.74 时是 −10.1 dB |
| 512 值不值 | 值：每个子带都更好，8.2–8.6 kHz 好 5.0 dB；680 只再多 2.1 dB；1024 不可实现 |
| 为什么实测阈值比模型低 11–12 dB | **未解决**，但对 256 和 512 完全一样 → 是共因，不是模型质量；见 §7 |

## 2. 数据自检

六段全部：`delay=125`、`gain_q12=0`、`bypass=True`、`prediction_pcm` 全零（真旁路）、
ref 有效区间 0–15360（尾部补零）。段间电平差 0.3 dB，可直接拼。

对照场次那 9 段里，`seg_3/4/8` 是音响待机（mic −37.5…−37.8 dBFS、ref 全零），
`seg_0/2` 的延迟是 124，只有 4 段能拼。`scripts/score_time_domain.py` 现在会自动剔除这两类段
并打印原因——这个坑 10-22 已经踩过一次，写进工具里了。

## 3. 模型不是分歧点

用同一批六段重拟合，与 A 交付的模型比：

| | 相关系数 | max\|差\| | ℓ1 |
|---|---:|---:|---:|
| 256 抽头 | **0.9996** | 0.0061 | 5.984 vs 5.957 |
| 512 抽头 | **0.9992** | 0.0065 | 7.838 vs 7.746 |

所以后面所有差异都不来自「谁拟合得更好」。`model_256_pad` 与 `model_256` 逐项相同，符合预期。

## 4. 时域口径下的真实抑制（逐段掐掉前 512 点）

| 模型 | 评价数据 | RMS | 峰值 | 300–1k | 1–3k | 3–6k | 8.2–8.6k |
|---|---|---:|---:|---:|---:|---:|---:|
| fit 本场 256 | 本场 | −9.91 | −7.46 | −2.3 | −5.4 | −11.2 | −18.4 |
| fit 本场 512 | 本场 | −11.24 | −10.78 | −4.0 | −6.6 | −13.4 | −23.4 |
| fit 本场 680 | 本场 | −11.64 | −10.04 | −4.5 | −7.0 | −14.0 | −23.5 |
| fit 对照 256 | 对照场 | −10.67 | −8.48 | −3.9 | −8.3 | −12.3 | −20.7 |
| fit 对照 512 | 对照场 | −14.99 | −8.45 | −10.1 | −13.1 | −15.6 | −25.5 |
| fit 对照 680 | 对照场 | −16.84 | −8.44 | −12.9 | −15.4 | −17.4 | −26.4 |

注意 300–1000 Hz 两批差 6 dB（−4.0 vs −10.1），而模型和抽头都一样。差别只在相干：
新批 0.49，旧批 0.74。**这不是模型能力差异，是这批数据在该频段的信噪比不够。**
一个 0.49 的相干意味着约 76% 的麦克风功率与参考不相关，那部分任何滤波器都减不掉。

## 5. 跨场次可迁移性：损失 1.6–3.0 dB，不是崩溃

| 抽头 | 同场次 | 跨场次 | 损失 |
|---|---:|---:|---:|
| 256 | −9.91 / −10.67 | −8.87 / −8.48 | 1.6 dB |
| 512 | −11.24 / −14.99 | −11.00 / −9.23 | 3.0 dB |
| 680 | −11.64 / −16.84 | −11.51 / −9.41 | 3.0 dB |

（每格是「拟合 A 评价 B」与「拟合 B 评价 A」两个方向。）

这条纠正了我 10-23 早些时候基于谱最大值给出的「跨场次塌到 0 dB」——那个结论用的是
不带门控的 `max|H−Ĥ|`，被单个边缘 bin 决定。时域口径下模型是**可迁移的**，
每次换场次丢 2–3 dB，属于正常。

## 6. 8.4 kHz：可复现、被抵消得很好，不是瓶颈

十个段（两批）全部在 8345–8416 Hz 出现峰，幅度 +9.7…+11.1 dB，半功率宽度 405–811 Hz。
这是稳定特征，不是伪影，也不是漂移。

而模型在那一带的抑制是 **−18.4 dB（256）/ −23.4 dB（512）**，谱口径的 CD 也一致
（+16.2 / +20.8 dB）。所以**它已经被处理掉了，不需要单独做分频段或改摆位。**

A 表里「6–12 kHz CD 最差 −4.89」的负值来自 `|H|` 的零点：那里 `|H|→0` 而残差不为零，
比值必然是很大的负数，与「是否放大环路」无关。**判据应该是残差的绝对电平，
不是 CD 的符号**——这一点我 10-23 已经提过一次，这次给出可执行的替代口径：
只在 `|H|` 距峰值 20 dB 以内的频点上取残差（`scripts/score_time_domain.py` 用整条带能量比，
等价但更稳）。

## 7. 未解决：实测阈值比模型低 11–12 dB，且对两个模型完全一致

| | 模型预测抵消阈值 | A 实测 | 差 |
|---|---:|---:|---:|
| 256 | +6.54 dB | −5.5 dB | 12.0 dB |
| 512 | +10.58 dB | −0.5 dB | 11.1 dB |

**恒定的 11–12 dB 说明这不是模型质量问题**（那会让两个模型差得不一样）。
它能被一个共同因子解释，两个候选：

1. **残差起始电平低 + 判据要求饱和。** 抵消侧的残余起始在 −35 dBFS 左右（近底噪），
   旁路的起始就是激励电平。要「看到饱和」需要的超额增益与起始电平有关，
   所以抵消侧被**系统性高估阈值**。旁路侧差 3.9 dB，抵消侧差 11 dB，方向与此一致。
2. **残差通路的实际增益与标定不一致。** 那会同时抬高两侧，但旁路只差 3.9 dB，所以单独不足。

**一次实验可以判定（不需要改代码，也不需要啸叫）：**
在确认稳定的增益（例如 512 在 −4 dB）手动存一段 `mic` + `prediction_pcm` + `residual_pcm`，
比较 8.2–8.6 kHz 的 `|residual|/|mic|`：

- 实测 ≈ −23 dB → 残差本身是对的，模型没问题，**是判据把阈值测高了**，改判据；
- 实测 ≈ −12 dB → 残差真的变差了，那是通路/电平的问题，再查标定条件。

A 已经做了 `GUARD_CAPTURE_SAVED`，只需要在**未触发保护**的稳定点上再存一份。

## 8. 其它两条口径澄清

- **`max|H−Ĥ|` 与 `CD 最差` 是两个量**：前者是残差的绝对电平（决定起振阈值），
  后者是逐频点比值的最小值（可能落在 `|H|` 零点上）。两个都要报，但不能互相替代。
- **A 报的「绝对值整体低 6 dB、怀疑麦克风增益变了」：两批标定数据不支持这个解释。**
  两批电平差 12 dB，`max|H|` 只差 0.3 dB（10.19 vs 9.87）。麦克风增益若真变了 6 dB，
  标定里会直接体现。所以那 6 dB 出在闭环测量，不在麦克风。而且 ASG 是两个阈值之差，
  纯增益变化会自动抵消，解释不了 ASG 的缺口。

## 9. 复现

```text
python scripts/score_time_domain.py --data-dir <目录> --cross-dir <另一场次> --taps 256,512,680
```

输出 `run.txt` 与 `score.json`（本目录）。脚本会自动剔除静音段与延迟不一致段，
并对每段打印电平与延迟。

抽头换算：单 MAC 每抽头 3 拍 + 3 拍收尾，帧预算 2048 拍 → **上限 681 抽头**。
512 → 1539 拍；680 → 2043 拍（只剩 5 拍余量，不建议）。
