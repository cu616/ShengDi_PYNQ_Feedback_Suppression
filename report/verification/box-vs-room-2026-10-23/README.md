# 2026-10-23 B 线：512 已上板，但房间夹具的瓶颈其实在 8.4 kHz

> 数据：A 于 2026-10-23 交付 512 上板结果与房间夹具 6 段标定；
> B 用箱体标定数据（`training_box_v1` / `validation_box_v1`）与房间 4 段做对照计算。
> 本文数值为模型推算，不是实测 ASG。

## 1. 先确认 A 的 512 结果

| 项 | 值 | 说明 |
|---|---|---|
| WNS / WHS | +0.287 / +0.034 ns | 时序通过 |
| BRAM | 80% | 抽头翻倍后余量变小，**若再上 680 会不够** |
| 拍数 | 3×512+3 = 1539 < 2048 | B 于 10-22 的预算核算成立 |
| 回归 | 512 位流 + 256 模型补零 → 与 256 基线逐帧 bit-exact、延迟 114 帧 | 所以 512 的差异可归因到抽头数 |

**A 顺手修了 `audio_pl_replay.v` 的三处前向引用（xvlog 报错）。** 这条不是小事：
已发布的 256 位流用仓库里的源码重建不出来，意味着**可复现性此前是断的**。
这条要进 STATE 的"已验证/未验证"——现在修好了，但它说明 RTL 与位流之间曾经不一致。

## 2. 箱体：256 已经到平台，512 只多 0.31 dB

箱体 `validation_box_v1`（样本外）逐子带的 CD 最差：

| 抽头 | 300–1000 | 1000–3000 | 3000–6000 | 6000–12000 | 全带 ASG |
|---|---:|---:|---:|---:|---:|
| 128 | +2.90 | +4.68 | +1.25 | −2.56 | +5.03 |
| **256** | **+12.05** | **+7.86** | +1.19 | −2.80 | **+13.72** |
| 384 | +11.71 | +7.62 | +1.54 | −2.63 | +11.80 |
| **512** | **+13.37** | **+7.91** | +1.44 | −2.81 | **+14.03** |
| 680 | +12.19 | +7.13 | +1.30 | −2.85 | +12.55 |

**256 → 512 只多 0.31 dB，384/680 反而更低。** 所以箱体上"512 没用"这一点，
**在模型上就成立，不需要用闭环实测才能看出来**。原因是箱体 256 的低频 CD 已经是 +12 dB，
本来就没有余量可加。

## 3. 为什么箱体够、房间不够：不是"混响长度"，是 |H| 的绝对水平

A 的解释是"箱体冲激响应短、256 已覆盖"。这条**只对一半**：

| 夹具 | 峰值帧 | 能量 95% | 能量 99% | 256 抽头 = 256 帧 |
|---|---:|---:|---:|---|
| 箱体 training | 68 | 236 | 452 | 覆盖 95%，不足 99% |
| 箱体 validation | 69 | 225 | 315 | 覆盖 95%，不足 99% |
| 房间 seg_1+5 | 125 | 235 | 522 | 覆盖 95%，不足 99% |

**两者的 95% 能量点几乎一样（235 vs 236 帧）**，256 抽头对两者都只覆盖到 95%。
所以"箱体短所以够"这个说法站不住。

真正的差别在 **`|H|` 有多大**：

| 夹具 | 300–1000 的 max\|H\| | 256 的 CD 最差 |
|---|---:|---:|
| 箱体 | **+25.45 dB** | +12.05 |
| 房间 | **+4.70 dB** | −0.41 |

CD 是比值。**箱体的 |H| 有 25 dB，模型即使差 13 dB，CD 仍有 +12；房间的 |H| 只有 4.7 dB，
同样 5 dB 的绝对误差就变成 CD 负。** 换句话说：

> 房间夹具失败不是"模型对箱体好、对房间差"，是**房间的耦合弱，对模型误差的容错更小**。

这也解释了 512 为什么在房间有效：它把 300–1000 的 `max|Ĥ|` 从 −1.03 提到 **+5.09**
（实测 +4.70），残差降到 −9.45 dB，相对 4.7 dB 的 |H| 才有余量。

## 4. 8.4 kHz 的 +10 dB 共振：shipped 模型的瓶颈，重标定后消失

房间 6 段在 **8.3–8.5 kHz 有一个稳定的 +9~10 dB 共振**，不是单段伪影：

| 段 | 8345 Hz | 8368 Hz | 8392 Hz | 8416 Hz | 8440 Hz |
|---|---:|---:|---:|---:|---:|
| seg_1 | +10.03 / 0.96 | +9.74 / 0.85 | +10.07 / 0.94 | +9.52 / 0.95 | +8.59 / 0.94 |
| seg_5 | +9.49 / 0.97 | +9.63 / 0.87 | +9.71 / 0.92 | +9.17 / 0.95 | +9.13 / 0.96 |
| seg_6 | +9.04 / 0.93 | +10.25 / 0.94 | +9.61 / 0.94 | +8.88 / 0.91 | +8.80 / 0.90 |
| seg_7 | +10.12 / 0.96 | +10.09 / 0.88 | +9.55 / 0.87 | +9.34 / 0.96 | +9.63 / 0.95 |

（格式：`|H| dB / 相干`。六段一致，相干 0.85–0.98）

**形态上它就是起振点**：8416 Hz 的环路相位是 +18.8°（在 0° 附近），
`|H| = 9.17 dB`、`|H − Ĥ| = 2.69 dB` → 旁路应起振于 −9.17 dB、抵消于 −2.69 dB。
而低频最强的允许点 429 Hz 只给出 −4.10 / −2.14 dB。

**但这个瓶颈只属于 shipped 模型（低 SNR 标定）。** 用同一批高 SNR 数据重拟合的 256 抽头，
在同一点的残差是 **−12.10 dB**，余量 22 dB，根本不是问题：

| 模型 | 8368 Hz 的 \|H−Ĥ\| | 该点 CD |
|---|---:|---:|
| shipped 256（低 SNR 标定） | +2.56 dB | +7.33 |
| refit 256（高 SNR） | **−12.10 dB** | **+22.36** |

**所以 8.4 kHz 不是"必须处理的高频缺陷"，是低 SNR 标定在高频学不好的表现。**
把它当成硬件问题去改摆位或换音箱，会走偏。

A 的实测"旁路 −6 dB 稳定"与 shipped 模型预测的 −9.17 dB 仍矛盾，这条留待查
（可能是大信号下音箱在该频点压缩，或闭环测试时的夹具与采集时不同）。
但既然 refit 模型在那里余量 22 dB，**这条矛盾不影响下一步动作**。

### 4.1 refit 的瓶颈回到哪：300–3000 Hz

refit 256 的逐子带 CD：300–1000 **−0.38**、1000–3000 **−2.56**、3000–6000 +3.17、
6000–12000 +2.31。瓶颈回到中低频，与 A 的判断一致。512 把这两段翻正
（**+5.49 / +3.30**），并且四个子带**全为正**。

**所以完整答案是两步：先重标定（治病根），再上 512（补时长）。** 只做一步都不够。

## 5. 回答 A 的三个问题

### 5.1 "256 低增益就崩，是不是 CD 负 → 残余更强 → 补偿器饱和"

**链条方向对，但"崩"的本质是起振，不是器件故障。**

CD 为负 ⇒ 某些频点上 `|H−Ĥ| > |H|` ⇒ 同样的增益下 residual 比 mic 大 ⇒ 更容易撞 24 位
⇒ 保护在 15 ms 内切断。这条成立。

但要分清两件事：

- **保护触发 = 环路增益已经 > 1 = 已起振。** 所以 256 在 −3 dB 的"中止"就是起振，
  不需要完整包络也能判定。
- CD 最差（逐频点比值的最小值）与起振阈值（`max|H−Ĥ|` 的绝对值）**是两个量**。
  A 报的 −0.41 是前者，决定起振的是后者。两个都要报，不要互相替代。

### 5.2 "箱体 512 无用是不是同一机理的反面"

**是，但原因要换成 |H| 的绝对水平，不是混响长度**（见第 3 节）。
箱体 256 的 CD 全正、`|H|` 25 dB、容错大；房间 `|H|` 只有 4.7 dB、容错小。

所以"箱体冲激响应短、256 已覆盖"这句话不要写进报告——两者的 95% 能量点几乎相同。

### 5.3 "6–12 kHz 两版 CD 都为负，要不要单独处理"

**不需要单独处理。** 高频的短板是标定 SNR 造成的，重标定就解决了（第 4 节）：
shipped 在 8368 Hz 的余量缺口是 +2.56 dB，refit 是 −12.10 dB。

所以"6–12 kHz 要不要单独做分频段处理"这个问题的答案是**不用**，
但有两个前提要说清：

1. **不要用"加低通切掉 6 kHz 以上"来对付它。** 切掉之后旁路在该频点的 `|H|` 仍是 10 dB，
   环路增益从"抵消后 2.56"变成"旁路 9.26"，更容易叫。
2. **重标定之后要看一眼高频是否真的稳了。** 如果 refit 之后 8.4 kHz 的残差又变回正数，
   那才轮到考虑硬件（那个峰的来源可能是音箱自身的高频峰或近场反射，不是房间驻波——
   0.5 m 间距的驻波最低频率约 343 Hz，8.4 kHz 太高了）。

顺带：箱体的 6–12 kHz CD 在四个抽头下都是 −2.8 到 −4.5，但箱体在该频段的 `|H|` 只有 2.9 dB，
乘上 ASG 的余量后仍远小于 1，所以**箱体那条不影响稳定性，不要被负 CD 吓到**。
判断"某个负 CD 要不要管"，看的是该频点的 `|H|` 绝对值，不是 CD 的符号。

## 6. 对运行时保护改动的意见

**不建议放宽门限，建议改成"触发时记录"。**

- 保护本身是防线，放宽它会在真起振时失去切断能力。
- 而 A 需要的东西（起振点）其实已经有了：**保护触发就是"已起振"**。
  要更精确就在 −3 与 −2 之间二分，判据用"是否触发"，不需要完整包络。
- 但有一个必须排除的情况：**15 ms 的饱和可能是数字瞬时过冲，不是声学增长**。
  区分方法——保留保护，只在触发时**把 mic 与 residual 的前 15 ms 包络存下来**：
  - mic 在涨 → 真起振，当前判据成立；
  - mic 持平而 residual 削顶 → 数字问题，要另查（很可能是增益标度或对齐）。

这样既不放宽保护，又拿到了判据。改动只是"多存一段缓冲"，不碰中止条件。

## 7. 局限

- 8.4 kHz 那条的相位判断依赖 H 的估计精度（±10° 量级）。8416 Hz 的相位 +18.8° 距 0°
  只有 18.8°，在误差范围内，**所以"它允许起振"这个结论并不硬**。这也是为什么第 4 节说必须查。
- 箱体的 CD 表用的是 `validation_box_v1`，样本外；房间用的是 4 段交叉验证。
- 所有 ASG 都是线性小信号推算。A 实测箱体 10.8 dB、房间 4.0 dB，与模型（13.7 / 6.2）
  差 2–3 dB，来源未查清。
- BRAM 80% 是 512 的数字。若将来要 680 抽头，BRAM 会不够——这条要在选型时记住。
