## 1 已算清的内容

证据：[代数复核 JSON](captain-arithmetic-audit.json)。输入是 A 转发的六行表格，不是板上原始复数。

| Hz | 原报残差 | 按原报幅度及相位差计算 | 差值 |

| 400 | 0.459 | 0.477327 | +0.018327 |
| 4000 | 0.262 | 0.933988 | +0.671988 |

按打印精度（幅度三位小数、相位一位小数）给出的保守误差界，**六行均不自洽**。
400 Hz 的差值也超过舍入可解释范围；原脚本以任意 0.05 容差称其自洽，已修正。
差值方向不能判定是哪一列错。所有条件反解都保留“输入幅度正确时”的前提，不能把 ±39.4°当作实测相位。

其他核算：

- 8350 Hz、48828.125 Hz 下，39.4°若全由纯延迟造成，对应约0.640采样周期；152°对应约2.469。单频有符号与周期歧义，不能直接判断数字错位。
- 实际 +3 dB 档为5786/4096=1.41259765625。残差0.70对应幅度余量约0.09767 dB；3 dB幅度余量对应残差约0.50117。这是幅度约束，不是实测稳定裕量或ASG。
- 按原表相位推出的4000/8000 Hz残差，在+1 dB时分别乘得1.048/1.099，原B回复的1.48/1.55错误。幅度超过1与保护触发时间均不能单独选出可信列。
- 若陷波中心幅度为β，β=0.65对应−3.742 dB，比β=0.50的−6.021 dB浅。

令u为实际播放信号，s为外部声音，N为新增前向滤波器，D为实际前向调度，则线性未饱和模型为：

```text
e = s + (H - Hhat) u
u = g N D e
L = g N D (H - Hhat)
```

实际播放参考保证预测对象一致；N的相位仍进入环路，不能说陷波群延迟与稳定性无关。
滤波方案尚未批准部署，不能沿用旧B报告的β调节或上板步骤。

## 2 发现的代码线索

[recal_algorithm.py](../../../board/audio_replay/recal_algorithm.py) 的 `_phase_fit` 和 `_phase_validate` 均调用 `_align_pairs`：
按每份捕获的互相关峰，平移microphone后拟合或评分。实时硬件不会对输入PCM做同样的事。
这是一条待原件验证的线索，不是已确定根因。互相关峰变化也可能来自噪声、频谱形状或路径本身。

一个采样周期在8350 Hz约为61.56°，在400 Hz约为2.95°。因此低频验证通过不能排除高频时间基准误差。
本次脚本逐捕获输出原始时间轴下的响应和互相关峰；不平移、不拼接捕获、不修改lag_first。

- [diag_highfreq_phase.py](../../../scripts/diag_highfreq_phase.py)：只依赖NumPy；只读已有文件，不导入PYNQ，不操作硬件。

修复重点：

1. 用模型文件与Q20系数双SHA确认目标，不按L1近似匹配；不截断或补零系数。
2. 训练与验证分别计算，逐文件保留；不混入input/run/install捕获。开环、增益0、零模型、完成状态及PCM单位必须明确。
3. 不同采样率直接拒绝；拒绝不等长、非有限或削顶数据；NPZ禁止pickle。
4. 按已记录源窗口截尾，排除未知预测历史；H、Hhat在同一个频率网格上计算。导出实虚部，自动核验余弦恒等式。
5. 同时输出由相同参考卷积预测、同窗估计得到的残差，帮助识别有限Welch窗口对解析模型比较的偏差。
6. 相位斜率只在连续有效频带内拟合，不跨低相干缺口解缠。结果描述响应差异，不自动断言“延迟故障”。
7. 输出完整派生频谱与系数，**不含reference/microphone PCM**。谱点界不作为稳定性证明。
