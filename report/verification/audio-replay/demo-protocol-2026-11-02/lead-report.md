## 0 一句话摘要

早上真板跑通了"冷启动 → 一键标定 → BTN1 扩声 → SW0 拨上啸叫"的完整演示（演示点 +3.0 dB、`L1 2.170`、
旁路边界 +2.1 dB、ASG ≈3.2 dB）。之后为了"正对摆位能一键标定""延长到 60 秒""压缩标定耗时"做了
**6 次包改动、2 次判据代改、约 40 次真板运行**，功能目标（60 秒、4 段训练、新判据、+1.0 dB 演示点）
都达成了，但**始终无法复现早上的 +3.0 dB 扩声效果**。核心未解释项：**声学路径实测比早上强约 4.7 dB**
（405 Hz 处 `|H|` 0.667 → 1.14~1.29），而现场声明环境未变。

## 4 问题清单（按"是否已解释"分类）

### 4.1 已定位且有证据

1. **`L1 ≤ 4.0` 判据缺陷**：`L1` 是最坏情况上界、按绝对尺度卡，等于按最坏情况拒收；已由 B 书面提案、
   A 代实施改为 `max|conv|<0.30`。产品链路已实测生效（`L1 4.117` 被接受）。
2. **`REJECT_SCALE` 重试白烧时间**：h 与激励电平无关，实测三次 L1 几乎不动（4.455/4.467/4.339）；已去掉。
3. **标定耗时**：186 → 150 s（训练段 6→4）。余下大头：拟合 53 s、每段位流重下 4×7 s。
4. **两个不同的保护来源**：输出饱和（`guard`）与麦克风输入满幅（bit22 `input_overload`），过去被混用；
   已分开记录。高增益下更容易触发的是**输入满幅**。
5. **旁路 0.03 s 瞬断**：多次测量停在同一帧数（1289 帧），形态像**起跑瞬态**而非声学增长。

### 4.2 未解释（需要队长判断）

| # | 现象 | 证据强度 | 已排除 |
|---|---|---|---|
| U1 | **声学路径比早上强约 4.7 dB**（405 Hz `|H|` 0.667 → 1.14~1.29） | **强**（单音五次、跨重启、跨包、跨标定复现） | 板子状态、线缆接触、模型元数据 |
| U2 | **8.4 kHz 存在 `|H| ≈ 1.12` 的耦合峰** | 强（单音实测），但**时有时无** | 充电头（已换回原 USB 口） |
| U3 | **产品偶发"卡死"**：进程 84% CPU、`wchan=do_select`、状态文件 20 分钟不更新；重启服务即恢复 | 中（发生 3 次，均有现场记录） | 算法子进程超时（有 150 s 兜底） |
| U4 | 早上 +3.0 dB 可用、现在 +3.0 dB 失稳，而用户保证现场环境未变 | — | — |

## 5 关于 U1/U4 的可能原因（假设与强弱，供队长判断）

| 假设 | 支持 | 反对 | 强弱 |
|---|---|---|---|
| H1 音响音量旋钮/位置变化 | 4.7 dB 增量正好对应距离减半或音量变化 | 用户明确保证未动；`hp_volume` 配置未变 | 中（物理上最像，但被现场否认） |
| H2 Codec 模拟增益实际值与配置不符 | 4.7 dB 量级符合 PGA/DAC 音量步进；驱动只写部分寄存器（`0x400A/0x400B/0x400C/0x400D`、`0x4023/0x4024`），**未做全寄存器回读比对** | 寄存器写入值由配置确定、每次调用都写；断电重上电未改变 | 中 |
| H3 麦克风/音响接线或阻抗变化 | 重插后无改善 | 排除 | 弱 |
| H4 早上"成功状态"对应的物理/电气条件与现在不同，但差异未被记录 | 早上没有单音 `|H|` 基线，只有模型推算值 | — | **中高（记录缺失本身是风险）** |
| H5 标定流程/数据口径差异（如 morning 场景 `2a20c3e9` 的实际采集条件与后续不同） | 场景 ID 不同、`hp_volume` 相同 | 训练参数一致 | 中 |

> 注：`2a20c3e9` 场景的训练原件仍在板上 `~/.local/state/shengdi/runs/2a20c3e9…/io/`，
> **可直接用同一套单音/卷积分析对早上的原件重算 `|H|`**，这是区分 H1/H2/H4/H5 最便宜的一步（纯离线，不动硬件）。

## 6 建议的下一步（按优先级）

### P0（离线、1 小时内、不需要现场）
1. **对 `2a20c3e9` 场景的训练原件做同口径分析**：算 ref→mic 的 `|H(f)|`，与今天的原件逐频对比。
   若早上的原件就是 0.667、今天的是 1.15，则**路径确实变了**（U1 成立），H4 权重上升；
   若早上原件算出来也是 1.1 左右，则**早上的"0.667"是模型口径问题**，方向转为查模型/拟合。
2. **把 `|H(f)|` 单音基线写进流程**：以后每次换摆位/换设备，先测 405 Hz/8.4 kHz 两个点，30 秒完成，作为可比基线。
   （今天最大的教训就是"早上没有这个基线"。）

### P1（需要现场配合）
3. **针对 U2**：在 8.4 kHz 附近做窄带扫频，确认它是真实声学共振还是电学耦合（拔掉音响/换线各测一次即可判定）。
4. **针对 U3**：卡死复现时用板上已有的 `gdb`/`strace` 抓调用栈（工具已确认存在），定位到具体阻塞点。

### P2（需要 B/C）
5. **U1 若确认为真实路径变化**：由 B 判断是否需要在判据里增加"路径增益基线"以及是否有必要做**自适应/在线阻抗/路径监测**；
   由 C 决定是否把 `hp_volume` 与判据绑定。
6. **交付链收敛**：今天所有临时包（`33fad35b`/`db1b7d97`/`f5cf4fce`/`42da66b5`）都不在 C 交付链，
   **正式交付必须由 C 按最终参数重新出包**，否则"装的是什么"与"C 交付了什么"对不上。
