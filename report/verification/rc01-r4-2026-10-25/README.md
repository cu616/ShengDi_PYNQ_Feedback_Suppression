## 0 一句话结论

**在 −14 dB 这个固定工作点上，OFF 与 ON 都远在稳定区内**（预测余量：OFF −21.4 dB、ON −11.2 dB，
按"允许增益 + 工作点增益"算）。所以这一轮跑出来的 `on_minus_off_response_rms_db`
**预测只有 +0.02 dB**（单 bin 范围 −0.84…+0.88），比配对门禁 1.5 dB 小一个量级。

**结论：r4 在 −14 dB 下没有分辨 OFF/ON 的能力，只能用来否证，不能用来证明收益。**
这与 C 自己写的"−14 dB 跑完／保护未触发／60 秒工程通过都不能单独写成抗啸叫成功"是一致的，
而且这里给出了定量理由，不是口头谨慎。

两个口径全程分开，不合并：

- **口径 A（稳定裕度）**：某点允许的最大线性增益。OFF = `1/max|H|`；ON = `1/max|L|`，
  `L = (H − Ĥ)·e^{−jω·2}`。另给正实轴穿越作为第二套估计（Nyquist 近似）。**都不是实测阈值。**
- **口径 B（受迫响应）**：源一直开着时麦克风电平的 ON/OFF 比。稳态下 `mic/source = H/(1 − g·L)`，
  所以比值 = `1/(1 − g·L)`，按 `|H|²` 加权。**这正是 r4 的 `on_minus_off_response_rms_db` 会测到的量，
  它不是抵消深度，也不是 ASG。**

## 3 三个问题的正面回答

### 3.1 哪些已覆盖频段预计改善

**300–1000 与 1000–3000：方向可判，且两套估计、两个窗长、两种划分同向。**
留出 8192 上分别是 +10.17 / +12.20 dB（口径 A 下界），4096 上 +11.13 / +14.60；
正实轴穿越给出同一方向（−6.46/+6.60、−2.51/+9.96）。这两个带的门控覆盖 77% / 93%，
限制点在四个表里都稳定：300–1000 是 417–447 Hz，1000–3000 是 1526–1752 Hz。

**8200–8600：方向不可判，写未知。**
这一带 67 个 bin 只有 **5 个**过门控（8321、8327、8351、8357、8416 Hz，相干 0.80–0.85），
其余 62 个全被挡在 0.8 门外，**包括 8368 Hz 的 +6.64 dB 峰顶（相干 0.770）与 8380 Hz（+6.27，0.757）**。
对照：训练 10 段里这一带能过 10 个 bin（14.9%），全带最差点正好落在 8368 Hz；留出 6 段只过 5 个、
最差点退到 8357 Hz。**同一个峰顶在两个划分里一个进门控一个没门**——这本身就说明 8.4k 的结论不稳。
所以表里 +19.00 dB 只是那 5 个边沿 bin 的数字，**不能当这一带的结论**，更不覆盖峰顶。

### 3.2 哪些可能恶化

- **已覆盖 bin 上，四个表全部 `更差 bin = 0`**：没有任何一个过门控 bin 的 `|L| > |H|`。
  换句话说，在这个 H 上，FIR 不增加任何已覆盖频点的环路增益。
- 但这句只对**这一份 H** 成立。换场次后 H 会变（10-21→10-24 实测 8.38 kHz 变 −5.98 dB / +39.5°），
  局部估计不能排除某些 bin 在新场次翻正。**所以"不会恶化"是条件结论，不是保证。**
- **真正的高风险在未覆盖区**：全带只覆盖 29%，8.4k 带只覆盖 7.5%。那里既没有"改善"的依据，
  也没有"不恶化"的依据——**一律记未知**。

### 3.3 哪些实测会否定预测，哪些只算证据不足

见 §4，两栏分开。

## 4 否定条件 vs 证据不足

**A. 出现即否定上述预测（说明模型/口径有问题）**

1. 门禁通过、源在窗内、无削顶，**−14 dB 下 2.52 s 内保护触发**或 `growth_monitor` 报 `observed_growth`。
   预测余量 11–21 dB，这不可能同时成立。
2. **OFF 与 ON 的受迫响应差 > 1.5 dB 且方向相反**（ON 明显更响）。预测 |Δ| < 0.15 dB；
   1.5 dB 以上的差不能用"FIR 有没有开"解释，说明臂间还有别的变量（电平、门禁、场景）。
3. 任一已覆盖 bin 的实测环路行为与"OFF 更差、ON 更好"相反（例如 OFF 稳、ON 起振，且配置已核实）。

**B. 只是证据不足，不能支持也不能否定**

1. `on_minus_off_response_rms_db` 落在 ±1.5 dB 内——预测本来就是 +0.02 dB，**这个指标分辨不了**。
2. 保护未触发、−14 dB 跑完、60 s 工程通过——**OFF 臂也应如此**，零信息量。
3. 配对因 `pair_path_drift > 1.5 dB`、`stop_reasons` 非空、`source_response.valid != true`
   或 `recovery_ok != true` 而不合格——这是配对资格问题，不是预测对错。
4. 8.4k 带无结论（覆盖 7.5%）。
5. 只有一个 repeat 有效（`repeats=2` 只要有一个不合格就只剩单次，方向无法确认）。

**C. 属配置错误，单独归类（既不是否定预测，也不是证据不足）**

装配的 `coefficients_sha256` / `file_sha256` 与 manifest 不符、`gain_q12` 被改、EQ 不是 identity、
源 sha 不符——按协议这些会直接把 `configuration_matches` 判掉，**不进结论**。

## 5 频域近似与有限时长受迫响应的差别（C 要求写清）

1. **估计器**：Welch 交叉谱是 8192 点窗（0.168 s）、段内 3 个窗、跨段累加的平均稳态 H；
   现场是 2.52 s 连续、滤波器固定。前者给"平均传递函数"，后者给"一段时间里的响应"。
2. **口径 A 的物理含义**：它回答"稳态下这个环路有没有自激模态"，是特征值问题，与源无关。
   **它不预测 2.52 s 里麦克风电平会怎么变。**
3. **口径 B 的物理含义**：源在环内，`mic/source = H/(1 − g·L)`。只要 `g·|L| << 1`，
   `1/(1−g·L)` 就贴近 1，于是 ON 与 OFF 的差只有零点几 dB。这就是 +0.02 dB 的来源，
   **也是"测不到差别"不等于"抵消没用"的原因**——抵消的价值体现在"还能再拧多少 dB"，
   而这一轮根本不拧。
4. **时间尺度**：`T_loop ≈ (125 + 2)/48828 ≈ 2.6 ms`；超 unity 每 1 dB 的增长约 `1/T_loop ≈ 385 dB/s`。
   所以任何 `g·|L| > 1` 的 bin 会在 0.1 s 量级内到 +30 dB，保护一定先动。
   反过来说，"2.52 s 没保护"只能说明所有**已覆盖** bin 的 `g·|L| < 1`（在估计噪声内），
   推不出余量还剩多少——这正是 §0 那句"只能否证"的依据。
5. **电平差**：H 是在 −12 dBFS 注入下标定的，现场源是 −24 dBFS。H 随电平变（我们踩过这个坑），
   所以口径 B 的 ±0.15 dB 结论比口径 A 更依赖"两个电平下 H 差不多"这个假设。
6. **单位提醒**：C 写的"同帧响应窗 14408 帧"，按 48828.125 Hz 折算为 0.295 s，
   与 2.52 s 的 run 长度不一致。若这不是采样点单位，请给换算；本节的时间尺度论证
   对任何 ≥0.295 s 的窗都成立，不影响结论。
