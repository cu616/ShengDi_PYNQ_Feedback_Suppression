# 技能包贡献规范（给其他会话 / 其他同学）

本仓库的 `skill/` 是按评测指南 3.3.5.2 提交的技能包。任何人（包括其他 AI 会话）都可以贡献，
但必须遵守下面的格式与证据要求。

## 1. 什么内容值得收进技能包

指南把技能包限定为四类之一或多种；贡献前先判断属于哪类：

| 类型 | 例子 |
|---|---|
| 提示词工作流 | 一组经过验证、能稳定完成某类任务的提示词模板 + 使用说明 |
| 案例模板 | 下一个题目能直接套用的工程骨架、脚本模板、报告模板 |
| 校验脚本 | 自动比对黄金参考、检查资源/时序、验证可复现性的脚本 |
| 踩坑清单 | 结构化整理的常见错误与定位方法，含触发条件与排查步骤 |

收进技能包的标准是**可复用性**：换一个题目、换一块板卡，别人还能不能用。

## 2. 目录与命名

```
skill/
├── README.md                 # 索引（新增技能必须在这里补一行）
├── CONTRIBUTING.md           # 本文件
└── <skill-name>/
    ├── SKILL.md              # 必需，固定五节
    └── scripts/              # 可选：可直接运行的校验脚本
        └── <script>.py
```

- `<skill-name>` 用英文小写字母、数字、连字符；不得用中文、空格、下划线以外的特殊字符。
- 一个技能一个目录；不要在 `skill/` 根目录堆散文件。

## 3. `SKILL.md` 模板（复制后填写）

```markdown
---
name: <skill-name>
description: <一句话说明用途与边界，给人和其他 AI 都看>
---

# <标题>

## 适用场景
- 什么情况下用；前置条件（板卡、软件版本、数据、权限）。

## 使用方法
- 可直接执行的命令，或可直接粘贴的提示词模板（按步骤编号）。
- 每一步写清：输入、预期输出、失败时看哪里。

## 已验证效果
- 在什么环境验证过（板卡型号、工具版本、数据来源）。
- 证据链接：指向 report/ 或 docs/log/ 的具体文件与提交号。
- 明确“未验证”的部分，不要写成已验证。

## 失效条件
- 哪些情况下这个技能不成立或必须重新验证。
- 常见误用（例如把开环预测当闭环 ASG）。

## 来源
- 从哪些失败或观察总结而来，保留原始记录位置（日志/提交号/证据文件）。
```

## 4. 硬性要求（评审会看的）

1. **只写验证过的内容**；未验证的标“候选”，并写明还缺什么证据。
2. **每条结论可追溯**：给出文件路径 + 提交号或日志位置，不接受“我记得”。
3. **不泄露**：账户令牌、校园网凭据、私人录音、第三方未授权材料一律不进技能包。
4. **复用他人代码保留来源与许可证**。
5. 通用性优先：能脱离本队题目复用的 PYNQ 技能，单独成项（指南 3.3.2 有加分）。

## 5. 提交前检查清单

- [ ] 目录名与文件名纯英文小写（数字/连字符），无中文、空格、特殊字符
- [ ] `SKILL.md` 五节齐全：适用场景 / 使用方法 / 已验证效果 / 失效条件 / 来源
- [ ] `skill/README.md` 索引表已补一行（含适用场景、已验证效果、失效条件）
- [ ] 所有引用的证据路径存在（断链检查见 `python scripts/check_docs.py`）
- [ ] 没有把未验证内容写成已验证
- [ ] 没有敏感信息与私人数据
