# 复频响表的自洽性审计

## 1 适用场景

手上有**一份辨识结果表**，同时给出 $\lvert H\rvert$、$\lvert\hat H\rvert$、两者相位差、以及复残差 $\lvert H-\hat H\rvert$，需要判断"某个频点残差大"到底是模型差、还是这几列根本不是同一口径算出来的。

典型触发：一次现场失稳之后，有人给出"某频点相位失配 N 度、导致环路越界"的结论，而你要决定是重拟合模型，还是先质疑这个数。

**只有四列齐全时本方法才成立。** 缺复数就只能阻断，不能补。

## 2 使用方法

### 2.1 先验自洽，再谈根因

这四个量必须满足余弦定理，物理上没有第二条路：

$$\lvert H-\hat H\rvert^2=\lvert H\rvert^2+\lvert\hat H\rvert^2-2\lvert H\rvert\lvert\hat H\rvert\cos\Delta\varphi$$

运行 `python scripts/verify_complex_response_table.py`（内置 2026-11-02 的实例，可直接复跑）。

判读规则：

- 偏差 $\le 0.05$：该行自洽，可以往下用
- 偏差明显但所有行同号：某一列整体偏移，最常见是相位列取了 $\angle H$ 而不是 $\angle H-\angle\hat H$
- 偏差方向不一致：几列来自不同数据或不同频点，**整张表作废**

实例（`report/verification/audio-replay/demo-protocol-2026-11-02/lead-report.md` §12.4）：六行里只有 400 Hz 自洽（偏差 0.018），其余五行差 0.3–1.5，且 8500 Hz 的方向与另外四行相反。8350 Hz 报 $-$152°、残差 0.815，按余弦定理应为 2.286。

### 2.2 用已发生的行为决定哪一列可信

表里有列不可信时，不要猜，用现场已经发生的事实当裁判：

- 若按余弦值推出的环路增益与实测起振时间矛盾，余弦分支不成立。实例：8350 Hz 按余弦值环路 3.23，起振应在毫秒量级，但实测 0.06 s 才触发保护——0.06 s 更符合"环路略大于 1"。
- 若某频点按某分支算出的环路已越界，但该增益下系统能长时间跑满，该分支不成立。实例：4000/8000 Hz 按余弦值环路 1.32/1.38，而 +1 dB（×1.123）下这两点更高，却稳定跑满 60 s。

两个方向都试过之后，本例结论是**残差列更接近真实、相位列不是 $\angle H-\angle\hat H$**；由残差反解，8350 Hz 的真实相位差约 $\pm39°$，不是 152°。

这个差别决定修法：39° 只要约 0.1 帧的延迟修正，152° 要 1.9 帧。"差一点"和"差很多"是两种病。

### 2.3 相位误差在高频被放大，低频验证通不过高频

同样一个采样帧的时延偏差，在不同频率上对应的相位误差差一个数量级：

$$\Delta\varphi=360°\cdot f\cdot\tau,\qquad \tau=1/f_s=20.48\ \mu s\ (f_s=48828.125\ \mathrm{Hz})$$

| 频率 | 1 帧对应的相位 |
|---|---|
| 400 Hz | **2.95°** |
| 4 kHz | 29.5° |
| 8.35 kHz | **61.6°** |

所以"300–460 Hz 验证通过、8.3–8.6 kHz 现场失稳"可以同时为真。本例的独立验证只覆盖 300–460 Hz，该带内相位差 16.9°、环路 0.65，看起来很好；而 8.3 kHz 处同一个模型已经偏了六十度量级。

**验证带宽必须覆盖 $\lvert H\rvert$ 的峰值频段**，否则"验证通过"与"能稳定工作"会持续脱节。

### 2.4 要测就测群延迟差，不要只测单点相位

单点相位差会被舍入和口径污染；相位差对频率的斜率不受影响：

运行 `python scripts/diag_highfreq_phase.py --run-dir <采集目录> --model <model.json>`，输出每频点的 `H_re/H_im/Ĥ_re/Ĥ_im/Δφ/|H−Ĥ|/相干`，并对 300–10000 Hz 的相位差做线性拟合，给出**等效群延迟差（帧）**与拟合残差 RMS。

判读：残差 RMS 小（十度以内）说明主要是延迟问题；残差大说明是模型形状问题。自测（`_inbox/2026-10-26_bindcapture_rewired` + `models/room_v1/rewired_512_20261026.json`）测出 −0.4307 帧、拟合残差 9.9°。

## 3 已验证效果

- **余弦定理检验在真实报告上抓出"六行里五行不自洽"**。该结论此前被当作现场失稳的根因使用（`lead-report.md` §12.4、§12.6），复核后该数字不能再作为依据。六行偏差依次为 +0.018、+0.672、+0.608、+1.471、−0.448、+0.301。
- **群延迟拟合在本地一组数据上给出可复现的 −0.4307 帧、拟合残差 9.9°**，脚本可重跑。
- 两个脚本都能直接跑起来并给出与报告一致的数值：`scripts/verify_complex_response_table.py`、`scripts/diag_highfreq_phase.py`。

以上都是**离线核算**，没有上板结果；本节不主张任何稳定裕度改善。

## 4 失效条件

任一条成立就不能下结论：

- **只有幅度与残差、没有相位，或缺复数**：只能做幅度一致性检查，不能判相位。
- **表是低精度舍入值**：$\lvert H\rvert$、$\lvert\hat H\rvert$ 只保留 2–3 位时，残差小的行（<0.05）误差会被放大，0.018 量级的偏差不能判为"有罪"。
- **用行为反推时，必须确认该次运行真的起振过、且知道当时的数字增益**；增益不明则反推无效。
- **`lag_first` 与前向调度延迟的归属必须单独核**，不能靠整体平移数据让表变好看——那等于换一套口径去凑结论。
- **本方法只判"这张表能不能用"，不判"系统稳不稳"**。$\lvert$残余环路$\rvert>1$ 也不等于必然自激，还要看相位是否落到 $2k\pi$。
- 不适用于只有单频点数据、无法做频率拟合的场合（此时只能用 2.1 的自洽性检验，用不了 2.4）。
