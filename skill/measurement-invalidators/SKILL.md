# 结论之前先校验测量：四个会让对比失效的陷阱

本页讲的不是"怎么测得更准"，而是**怎么在写下结论前发现这次测量本来就回答不了问题**。
四条都来自本仓库 2026-10-26/27 的现场，每一条都曾让我得出错误结论并当场撤回。

## 适用场景

- 你要**分两次（两组）运行再比较**某个频段/统计量的差异。
- 你打算用**硬件计数器为 0** 来论证"这件事没有发生"。
- 你的读数**不随激励变化**，你正准备从声学/算法角度解释它。
- 前置条件：拿得到原始捕获（npz/csv），知道计数器的触发条件，知道参考信号是什么。

## 使用方法

四条按顺序过；任何一条不通过，**这次对比就不能进结论**，先修测量。

### 检查 1：计数器的触发条件是不是结构性为 0

问自己一句：*这个计数器要触发，需要某个量非零吗？那个量会不会本来就是零？*

典型例子（本仓库实测）：残差越界计数器的判据是 `|mic − pred| > 满幅`。
零系数时 `pred ≡ 0`，于是 `mic − pred ≡ mic`，**只要麦克风不溢出，这个计数器永远不可能触发**。
结果：一次真实的环路失控（麦克风 RMS −4.8 dBFS、21% 样本贴满幅）被记成"无异常、completed"。

判据：把计数器的**代数表达式**写出来，代入当前配置，看触发条件是否退化成恒假。

### 检查 2：满幅普查（rail census）与计数器对账

在捕获里数贴满幅的样本数，和状态里的计数对账：

```bash
python scripts/invalidate_check.py --npz <capture.npz>
```

- 贴轨样本 > 0 而计数器 = 0 → **计数器看不见这类事件**，不能用它论证"没发生"。
- 贴轨样本 = 计数器（例如 8 个贴轨、计数 8）→ 捕获**确实覆盖**了事件，可以归因。
- 只看"满幅"三个字不足以判性质：要看**持续时长**。本仓库一次 0.5 ms 的 24 帧尖峰是瞬态，
  而连续 3 个 2048 帧块压在 −1 dBFS 才是失控形态。**满幅本身不是结论。**

### 检查 3：跨次比较前先验证声源是稳态的

分两次采样比较某个频段的电平，只有在**声源内容相同**时才成立。
判据：把指标按块算出来，看块间波动与你要测的效应谁大。

```bash
python scripts/invalidate_check.py --npz <a.npz> <b.npz> --metric band-share --band 300 360
```

- 块间跨度 **大于**待测效应 → 比较无效，必须换稳态源（白噪）或做同段内容对齐。
- 本仓库实测：同一个臂在两个会话里，300–360 Hz 占比分别是 0.008–0.278 与 0.031–0.713，
  跨度约 30 dB，**两臂顺序直接反转**；换成板卡白噪后差异稳定在 6.8–7.9 dB 才可用。

### 检查 4：读数不随激励变化时，先怀疑换能器/接线

若把激励改大 20 dB 而读数**一动不动**，那已经不是"信号小"，而是通路上某处恒定了。

1. 固定激励，只改一个量（源电平或增益），看读数是否按比例变化。
2. 不变化 → **先查接线再谈声学**。本仓库实测：麦克风电源线松动时 ADC 恒读 −4.2 dBFS，
   与源电平、与增益都无关；重插后底噪回到 −35.1 dBFS，同一位置峰值完全不同。
3. 这条代价最大：当天因此**三次采集判废**，并把一个"可用工作点"写进了记录又撤回。

## 失效条件

- **检查 3 只对"跨次比较"有效**：单次测量内的相对量（同一窗内的比值、投影对比度）不受声源非稳态影响，
  不要拿这条去否定本来正确的同窗相对判据。
- **贴轨普查不等于归因**：满幅可能来自输入过载、换能器饱和或环路失控，三者用满幅本身分不开；
  必须配合"持续时长"与"预测/参考是否存在"才能定性质。
- **计数器为 0 只在你知道它的触发条件时才无意义**；若计数器确实覆盖了该事件类型，0 仍然是有力证据。
- 块间跨度判据依赖分块大小；块太短会把内容起伏当成非稳态，块太长会掩盖短事件。
  本页用的是 2048 帧（约 42 ms），换采样率要按时间尺度重算。
- 换板卡/换驱动后，计数器语义与满幅定义都要重新确认，不能照搬。

## 来源

四条均来自 2026-10-26/27 的现场失败，逐条对应：

1. **计数器失明**：我把 `prediction_saturations=0` 当作"不是声学再生"的证据，并据此否定候选模型；
   第二天把捕获里的麦克风流拉出来，才发现零系数臂麦克风已顶满。
   记录：`silent-analysis-2026-10-27.json`、`candidate-failure-evidence-2026-10-27.json`。
2. **满幅 ≠ 失控**：候选臂保护停机，我起初把两臂都判为"再生"；块级包络显示零臂是 25 dB 台阶式失控、
   候选臂只是 24 帧瞬态。队长当场纠正"输入满幅不能直接判为声学再生"。
   记录：同上两份，以及 `docs/log/progress.md` 2026-10-27 条目。
3. **非稳态源**：我用手机播放的录音做两臂分次比较，得到"候选压低 12 dB"，下一次同条件却反向；
   改用板卡白噪后差异稳定。记录：`two-arm-stationary-2026-10-27.json`。
4. **接线**：一次现场中 ADC 恒读 −4.2 dBFS，先被我解释为"环路自激"；实际是麦克风电源线松动，
   三次采集判废。记录：`mic-fault-impact-2026-10-26.json`，以及
   `docs/lines/a-interaction-notes.md` 第七节的硬经验。
